# 单位间 Build 配合方案 v2 · 站位触发 + 机制变化（v6.37 设计草案）

> 版本：v2，日期 2026-11-20。状态：**方案，未改代码**。
> 相对 v1 的改动：v1 是"队友有某流派 → 全队常驻数值加成"（排表调数值），用户明确否掉。v2 改为**站位相邻才触发、且产生机制变化**（改变战斗行为，不是改数字）。
> 依据：基于实际代码接线点调研，所有落点均给出文件路径:行号。

---

## 一、设计定位

**核心命题**：流派配合是**阵型**，不是光环。

- 触发条件：我自己与具备配合流派的队友**格子相邻（曼哈顿距离 ≤ 1）**。
- 效果性质：**机制变化**——生成地形、转嫁伤害、连锁触发、改变目标选择等，改变"这局仗怎么打"，而非 +8% 减伤那种数值。
- 动态性：每次移动落格后**重算阵型**。走散即失效，靠拢即生效。敌人击杀/位移关键队友可破阵，形成攻防博弈。
- 每个单位仍只追求**一个主流派升到高 Lv**（与 §5.2 设计原则一致）。

**明确不做**：
- 不做"全队常驻光环"（v1 的常驻减伤/共享魂火，已废弃）。
- 不做"单单位双流派组合技"（B3，v6.36 已移除）。
- 不做需要新存档字段的复杂状态——阵型是战场实时计算。

## 三、六组配合（全部是机制变化 + 相邻触发）

统一结构：**条件** = 我与一个"流派 X 的友军"相邻；**效果** = 改变我方战斗行为。

| # | 名称 | 站位条件 | 机制变化（非数值） | 接线点 |
|---|---|---|---|---|
| F1 | **燎原** | 烈焰单位相邻灰烬单位 | 烈焰攻击命中时，在**灰烬队友脚下**生成一块燃烧地块（复用 `ash_tiles`），把单体灼烧变成"以队友为锚点"的地形扩散 | 攻击 `CombatManager.gd:348` + `drop_ash_tile:1369` |
| F2 | **铁壁护卫** | 任意单位相邻守护单位 | 被攻击时若有相邻守护友军，把该次伤害**转嫁**给守护单位（守护先吃伤害并触发自己的反弹），而不是给自己减伤 | 受击 `CombatManager.gd:1203 _apply_damage_with_effects` 入口 |
| F3 | **轮回链** | 任意单位相邻轮回单位 | 我击杀敌人时，额外在**轮回队友所在格**触发一次范围回魂火（以队友为圆心的小 AOE 回魂），把击杀收益变成"阵地化分布" | 击杀 `CombatManager.gd:938 _on_kill` |
| F4 | **血祭传递** | 任意单位相邻献祭单位 | 献祭队友扣的血量，转化为给我方的一次**额外行动**（战斗内 `can_act_this_turn` 重置一次），把"扣血"变成"换队友行动"而非换攻击力 | 回合开始 `TurnManager.gd:200` + `Unit.can_act_this_turn` |
| F5 | **余烬引爆** | 守护单位相邻余烬单位 | 守护反弹伤害时，若相邻余烬单位处于"魂火耗尽装填"状态，则**消耗其装填**触发一次必暴反击（把余烬的被动引爆变成主动连锁） | 反弹 `CombatManager.gd:1226-1244` + 余烬装填字段 |
| F6 | **灰烬火墙** | 灰烬单位相邻烈焰单位 | 灰烬队友铺下的燃烧地块，若我（烈焰）站在相邻格，地块**延长 1 回合**且踩中时附加灼烧 DoT（地块从一次性伤害变成持续区域控制） | `trigger_ash_tile:1390` + `tick_ash_tiles:1358` |

**设计要点**：
- 六个流派各至少参与一次（作为"锚点"或"受益方"），无废流派。
- F1/F6 是双向的（烈焰+灰烬互为条件，但效果不同）——**同一对相邻单位，从谁的视角触发不同效果**，鼓励思考"谁站哪格"。
- F2 的伤害转嫁呼应现有 `EnemyAI.gd:755-761` 的 `protected_ally` 护卫逻辑——玩家也能玩护卫阵型。
- F4 给"额外行动"是强机制，需限制：**每场战斗每对组合只触发一次**（战斗内临时标记，不写存档），否则过强。

## 四、落地的三个技术环节

### A. 阵型状态计算（每次移动后）

```
func rebuild_formation():
    synergy_state.clear()   # 键：Vector2i（我方单位格），值：Array[配合key]
    for unit in 我方存活单位:
        var my_dom = get_dominant_school(unit)   # 有效 Lv 最高的流派
        for neighbor in 相邻格友军:
            var n_dom = get_dominant_school(neighbor)
            var syn = lookup_pair(my_dom, n_dom)  # 查 F1~F6 表
            if syn: synergy_state[unit.grid_cell].append(syn)
```

- 挂点：`Battlefield._on_player_movement_finished`（`:890`）与 `_on_ai_movement_finished`（`:899`），在 `drop_ash_tile` 之后加 `FormationManager.rebuild_formation()`。
- 同时也要在**单位阵亡**时重算（`CombatManager._on_kill` 末尾）——守护死了，护卫链就断了。
- `get_dominant_school` 用 `get_effective_school_level(unit, school)` 遍历六流派取最大（竞技场 `ArenaBattle.gd:834-842 _dominant_school` 已有同型实现可借鉴）。

### B. 效果钩子（在既有战斗流程里判状态，不改流程顺序）

每个 F 组的判定都是同一个模式：
```
if FormationManager.has_synergy(attacker.grid_cell, "F1"):
    ... 机制变化 ...
    SignalBus.request_hint_override.emit("燎原 · 火场生成", 0.9)
```
- 只在**动作发生的那一刻**查缓存（O(1) Dictionary 查询），不在每帧/每单位循环里做。
- 触发反馈统一走 `SignalBus.request_hint_override`（`SignalBus.gd:50`）+ 必要时 `request_screen_shake`（`:26`），复用 B1 觉醒反馈通道。

### C. 视觉可见（必须做，否则玩家不知道阵型在起作用）

1. **阵型连线**：相邻且形成配合的两单位之间画一条细线（复用 `HighlightManager` 的高亮能力，或新增轻量 Line2D 层）。分开走线断，靠拢线连——一眼可见。
2. **单位详情面板**：`Battlefield.gd:1238-1243` 的技能/词条行之后加"阵型:"行，列出当前生效配合（如"阵型: 燎原(与灰烬·相邻)"）。
3. **触发飘字**：机制触发时 hint + 飘字，沿用现有通道。

## 五、竞技场处理

**明确排除**：1v1 无相邻友军（`ArenaBattle.gd:36-37` 各只有一个 `UnitData`，无 `grid_cell` 概念，是纯数值对战内核）。`rebuild_formation` 在竞技场不调用。竞技场保留其单流派 B2 阈值质变与 B4 觉醒技。

**文档口径**：`GameplayDesignDoc.md` §5.2/§5.11 注明"站位阵型配合仅主线战棋适用"。

## 六、实施顺序与验收

### 批次 1（阵型基础设施 + 一个样板）
- `FormationManager` 的相邻判定 / dominant school / `rebuild_formation`；挂到移动完成与击杀重算；阵型连线可视；详情面板"阵型:"行。
- 只做 **F2 铁壁护卫**（最能体现"转嫁伤害"的机制变化，且可直接对照 EnemyAI 护卫逻辑）。
- 验收：守护与友军相邻时，友军受击转为守护承伤+反弹；把守护走开后同一攻击打在友军身上。

### 批次 2（地形类，F1 + F6）
- 燎原与灰烬火墙，复用灰烬地块系统。
- 验收：相邻时攻击生成/延长火场，分开时无地块变化；地块上的 hint 飘字可见。

### 批次 3（收益/连锁类，F3 + F4 + F5）
- 轮回链、血祭传递（含每战一次的触发上限）、余烬引爆。
- 验收：三个连锁触发都有飘字；血祭每战只触发一次；敌人击杀相邻单位后阵型连线断裂、效果消失。

### 全局验收
1. 走散/靠拢即时生效，阵型连线同步。
2. 敌人击杀或位移关键单位能破阵（可观察连线消失 + 效果不再触发）。
3. 六组配合都是机制变化，无任何"全队 +X%"的常驻数值光环。
4. 存档零变化；竞技场行为不变。
5. 所有脚本 gdtoolkit 解析通过。

## 七、风险与规避

| 风险 | 规避 |
|---|---|
| 相邻判定口径不一致 | 统一走 `FormationManager.are_adjacent`，不各钩子内联曼哈顿 |
| 阵型状态过期（单位死亡/位移后仍生效） | 移动完成 + 击杀 + 单位移除三个时机都重算；效果触发时再校验一次相邻 |
| F2 转嫁伤害导致守护瞬间暴毙 | 转嫁量设上限（如单次不超过守护当前 HP 的 50%），超出部分仍由原目标承担 |
| F4 额外行动过强 | 每对组合每战一次，且只对玩家方生效 |
| 玩家看不懂阵型 | 连线 + 面板 + 飘字三层反馈；配合名两字，机制一句话 |
| 敌人 AI 不会主动破阵 | 现有 `EnemyAI` 已有 ally_dist 抱团与近敌评分，先观察试玩；若敌人完全不针对，后续加"优先攻击阵型关键单位"评分项（独立迭代） |

## 附：v1 → v2 废弃内容

v1 的六组（燎原 +30% 灼烧 / 铁壁共鸣全队减伤 8% / 轮回共享击杀 +1 / 血祭链接回 3% HP / 余烬掩护 30% 必暴 / 灰烬引燃附加灼烧）**整体废弃**——它们是"有无队友流派"的排表数值，不满足"站位相关 + 机制变化"要求。v2 保留了配合名与流派配对，但全部重做为站位触发的机制效果。

### 实现要点与方案微调
- **F2 防秒杀**：转嫁量上限 = 守护当前 HP 的 50%，超出部分仍由原目标承担；用 meta 标记防止转嫁伤害递归触发护卫。
- **F4 受益方修正**：方案写"受益方是相邻献祭的队友"，实现时遍历队友并检查其 F4 锚点是否为本献祭单位（初版误写成献祭单位自己受益，已修正）；额外行动重置 `can_act_this_turn`/`has_attacked`/`has_moved`。
- **F5 装填口径**：以 `ember_crit_consumed == false` 为"装填待发"，引爆时消耗该装填，造成一次必暴反击 + 震屏。
- **视觉连线**：代码动态创建 `FormationLineLayer`（不改场景 .tscn），每组配合一种颜色，走散线断、靠拢线连，监听 `request_formation_changed` 刷新。
- **零存档字段**：阵型状态与血祭限次均为战斗内临时，重开战斗 `reset_battle()` 清空。

### 待实机验证
1. 相邻守护代承伤害、走开后不再代承；转嫁不会让守护被一击秒杀。
2. 烈焰攻击在灰烬队友脚下生成火场；灰烬地块相邻烈焰时延长并附加灼烧。
3. 轮回链范围回魂、血祭每对每战只触发一次、余烬引爆消耗装填。
4. 阵型连线与详情面板「阵型:」行随走散/靠拢即时同步；敌人击杀关键队友后阵型断裂。
5. 竞技场行为与改动前完全一致（无阵型连线/提示）。
