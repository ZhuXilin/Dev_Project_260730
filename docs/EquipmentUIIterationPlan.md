# 装备界面与装备本体 · 迭代方案

> 版本：v1（方案稿，尚未实施）　日期：2026-11-18
> 依据：全文精读 `EquipmentConfig.gd`（3162 行）及 6 个子组件、`SetBonusManager` / `AffixManager` / `ConnectedGroupCalculator` 三套管理器、`ShopManager` / `RecipeManager`、场景与数据配置。
> 原则：**以代码事实为准**，设计文档仅作背景。本轮不改任何游戏代码，仅产出方案供决策。

---

## 一、现状诊断（代码事实）

结论先行：系统功能是完整的，复杂度不在于"系统多"，而在于**信息全部糊在同一层、核心收益不可见、术语错位**。按严重程度排序：

| # | 病根 | 代码事实 | 玩家后果 |
|---|---|---|---|
| ① | **连通收益完全不可见（最致命）** | `ConnectedGroupCalculator.gd:159-220` 算出 attack/defense/hp pct（上限 +15%）、开局护盾、开局魂火，但界面从不显示；只在自动配装 `_evaluate_layout`（`EquipmentConfig.gd:2894-2904`）内部评分中使用 | 核心 Build 目标没有反馈，玩家"连了不知道赚了什么" |
| ② | **20×20 格子叠 4 层视觉编码** | 图标 + 流派色块 + 方向箭头 + 连通黄框全压在一个 20px 格子上（`EquipmentConfig.gd:1731-1802`），无图例；代码注释多处 v5.x "修箭尖贴边/尺寸不一致" | 编码脆弱、需记忆颜色与几何规则，看不懂 |
| ③ | **术语与操作错位** | "锻造"=单件重洗词条 500G（`:188-200,244-268`）又=多件合成 200G（`:218-220,301-369`）；"调整"=改方向（`:202-214`）但按钮不提方向；"熔合"（2 件 epic 同 tag）与"熔铸"（牺牲单位）毫不相干；`weapon_tab_btn` 实为商店、`talent_tab_btn` 在商店模式实为铁匠铺（`:169-177`） | 词不达意，操作靠猜；几乎全部操作只能拖拽，无点击替代 |
| ④ | **详情是一坨无层次文本** | `EquipmentConfigDetail.gd:123-145` 把防御/属性/连通/词条/套装塞进一个 `stats_arr`，`"\n".join` 一次吐出，仅 `--- 词条 ---` 纯文字分隔，字号 6 | 信息不可扫读，重点淹没 |
| ⑤ | **套装统计口径误导** | `TagStatsBar`（`EquipmentConfig.gd:480-527`）统计**全队**该标签件数，tooltip 却写"已激活 2 件套"；真实激活是**同单位 2 件**（`SetBonusManager.gd:17,59-72`） | 玩家以为激活了，实际没激活 |
| ⑥ | **反馈弱且易丢失** | 多数结果用 `_show_detail_in_zone` 写一行 6px 文本（`:1590/:2254/:296/:2805`），鼠标移开即被 `on_button_hover_exited → clear_zone` 清掉 | 操作反馈看不到 |
| ⑦ | **隐藏开关无提示** | 右键切换"叙事/数值"模式（`_input` `:2531-2539`）无任何 UI 说明；右下"自动配装"浮动按钮 z_index=100（`:335`）侵入感强 | 功能存在但用户发现不了 |

**工程层隐患**：`_build_ui_inner`（`:727-1085`）含上百处硬编码节点路径与像素偏移，任何操作后都 `_schedule_build_ui` 全量重建。这是"改起来贵、改了易碎"的根源，也导致上述视觉问题只能用打补丁方式累积。**因此本方案优先选择不碰该骨架的改动。**

## 二、核心思路：信息分三层

不是砍系统，而是把信息拆到三个层级，各归各位：

| 层级 | 回答的问题 | 呈现位置 | 内容 |
|---|---|---|---|
| **第 1 层 · 一眼层** | "这是件什么装备，我能不能用？" | 卡片正面（无需悬浮） | 图标 + 品质描边 + 流派色条 + 词条数角标 + 一句话定位 |
| **第 2 层 · 悬浮层** | "它具体给我什么数值？" | 悬浮详情面板 | 基础属性 / 词条 / 套装三个带标题小区块，字号放大、术语口语化 |
| **第 3 层 · 决策层** | "我为什么这样摆，摆对了没？" | 常驻全局面板 | 当前连通组实际收益（攻/防/血 +X%、开局护盾、魂火）、各流派套装进度 |

## 三、迭代方案（按投入产出比分档）

### A 档 · 纯展示层（不动玩法逻辑，风险最低，推荐先做）

| 改动 | 落点 | 说明 |
|---|---|---|
| 连通收益可见化 | `EquipmentConfigDetail.gd`，调 `ConnectedGroupCalculator.evaluate_groups()` | 代码全现成，只差展示；把 +X% 三属性、开局护盾/魂火口语化输出 |
| 详情分区 | `EquipmentConfigDetail.gd:123-145` | `stats_arr` 拆成"基础属性/词条/套装"带标题小区块，字号调大，套装写"同单位 2/2 已激活" |
| 卡片增强 | `EquipmentConfig.gd:1664-1802` | 品质描边 + 词条数角标 + 流派色条（逐步替代纯色块） |
| 图例 | 详情区加一张说明 | 黄框=连通（越粗组越大）/ 色块=流派 / 箭头=方向 |
| 套装口径修正 | `EquipmentConfig.gd:480-527` | 改逐单位统计并对齐 `get_unit_set_tier`，区分"全队 N 件"与"某单位已激活" |
| 反馈持久化 | `_show_detail_in_zone` 调用点 | 结果文本改为不被 hover 清除的状态条，替代 6px 一闪而过 |

### B 档 · 交互改进（收益高，需谨慎）

| 改动 | 落点 | 说明 |
|---|---|---|
| 术语统一 | `EquipmentConfigForge.gd:160-238`、`EquipmentConfig.gd:169-177` | 单件"锻造"→「重铸词条 500G」、"调整"→「调整方向 120G」、多件→「合成 / 熔合」；按钮写明**成本 + 后果**（原词条会被覆盖） |
| 合成前预览 | `EquipmentConfigForge.gd:541-705`、`RecipeManager.gd:44` | 把已算好的评分/品质概率/幸运率/额外产出/是否熔合/是否命中图纸抽成 `preview_craft()`，悬浮即告知预期产出，盲盒变可预期 |
| 不可逆加确认 | 复用 `ConfirmUI.gd` 的 `show_confirm` / `set_item_icon` | 单件锻造展示新旧词条对比、合成展示预期产物 |
| 点击购买备选 | `EquipmentConfigShop.gd:157` | 点击商品→自动装备到首个空槽，与拖拽并存 |
| 一键领取强化 | `EquipmentConfig.gd:1391` 已有"一键领取 (N)" | 强化为"一键装备到空槽"，降低产物二次拖拽 |
| 常量归一 | `economy_config.json` + `reload_config()` | `MAX_SLOTS`（配置 9 / 硬编码 3）、`FUSION_COST`、`REROLL_DIR_COST`（两处定义）收归配置 |

### C 档 · 结构性重构（改动大，最后做）

- 进阶特技 / 遗物被动 / 自动配装按钮默认折叠进"更多"
- 网格 / 列表视图切换，缓解 20px 格子的编码过载
- 拖拽 + 点击双模式统一；合并 `Drag.gd:246` 与 `:294` 两套重复的目标收集函数

## 四、装备本体如何更清晰（与界面分层是两回事）

| # | 改动 | 说明 | 归属档 |
|---|---|---|---|
| 1 | **词条所见即所得** | 词条现仅 hover 可见。商店卡片/掉落直接显示 1~2 条核心词条，让"这件和那件有什么区别"一眼可见 | A |
| 2 | **方向 → 接口化** | 箭头三角对玩家是几何谜题。翻译成"可连：上/下/左/右"的接口图标 + 对接颜色提示，配图例 | B（涉及卡片绘制） |
| 3 | **套装身份前置** | 每件装备标出"属于烈焰套（同单位 2/2 已激活）"，把 tier2 质变条件从附录文案提到卡片 | A |
| 4 | **品质=词条数梯度显性化** | 现有梯度 common1/rare2/epic3/legendary4（`AffixManager`），用角标在卡片上点出，建立"史诗比稀有强一档"的直觉 | A |

## 五、推荐路线与验收

**建议第一批**：A 档的「连通收益可见化」+「详情分区」+ 装备本体的第 1、3 点。理由：两子代理均将其列为最高 ROI，且几乎不碰 3162 行构建骨架，风险可控。

**验收标准**：
1. 悬浮任一防具，详情面板分区清晰，套装显示"同单位 2/2"而非全队数。
2. 常驻面板能看到当前连通组的实际数值收益，摆对/摆错有直观差异。
3. 扫一眼卡片即可判断品质、流派、词条数、套装归属，无需逐个悬浮。
4. 图例可解释黄框/色块/箭头的含义。
