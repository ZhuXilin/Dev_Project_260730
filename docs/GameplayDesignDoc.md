## 一、版本定位

v5 把《魂火》做成“状态管理 + 标签配装”的肉鸽：魂火负责短循环，6 标签贯穿系统，FORGE 是决策爆发点。实际游玩后暴露的问题是：**装备系统操作强度过高**。玩家大量时间花在比较词条、摆方向、凑连通、管理背包和覆盖装备上，而不是表达 build。

v6 的核心转向：

> **玩家通过选择组成 build，而不是花时间配装。装备的重要性来自“第一件即觉醒机制”，不是来自操作复杂度。**

v6 把玩家日常操作压缩为三类：

1. 开局主动技能 roll → 点单位落位；
2. 战后防具 roll → 点单位落位 / 覆盖 / 放弃；
3. BOSS 后或宝箱遗物三选一。

系统承担所有计算：槽位、方向、连通、词条数值、品质上限、套装判定、成本结算。

### v6 相对 v5 的核心变更

1. 地图装备界面**保留 EquipmentConfig**（v6.4 回退只读方案）：装备与遗物可拖拽调整位置，但开局 roll 的技能词条锁定，特技库入口禁用。
2. 商店不再是一个地图节点功能；防具获取改为**战后金币 roll**。
3. 开局选 3 单位后，从这些单位可装备的主动技能中 roll 3 次，形成随机起点。
4. 每单位技能词条上限 2 格：第 1 格开局 roll，第 2 格转职获得；两格锁定。
5. 防具从数值套装改为**单件觉醒机制 + 同流派并入升 Lv**。
6. `armor_slots` 语义改为**机制槽**：一个流派占一格，同流派后续防具不占新槽。
7. 魂栈改为**遗物商店**：售卖团队遗物 + 老虎机专用遗物，可刷新、可将已装备遗物拖入出售（v6.62）；防具商店 / 铁匠 / 光环不再存在。
8. 光环并入遗物：多数为持续型，少数产魂火光环为消耗型遗物。遗物分**团队槽（6 格）与老虎机专用槽（4 格）**两类，见 5.6。
9. 连通、箭头、装备界面单位交换位置从玩家层移除。
10. 单位升级改为**击杀敌人即时获得经验**（按敌人强度配置，唯一来源），自动升级；装备界面不再有升级按钮。详见 5.7。
11. 战后结算不再送防具；宝箱不再提供防具选项。
12. 竞技场已同步主线核心机制（见 5.11）。
13. 献祭 / 熔铸不再产出强力单位或专属防具，改为**单位赋能**：把献祭单位的基础数值加到幸存单位上使其超级化，机制合入英灵殿节点（v6.62）。详见 5.10。
14. 胜利条件不再配在地图节点上，改由**每张战场地图场景内的 `VictoryObjectiveTrigger`** 承载，默认全灭，战场与地图节点共同识别（v6.62）。详见 5.9。

### 保留的 v5 骨架

魂火两态（燃烧/正常，归零无增益）、命中回魂火、魂火跨节点继承、六流派标签、四层循环、七组张力、献祭熔铸单位（v6.62 起改为单位赋能）、遗物三选一、局外魂成长、派遣、剧情、竞技场、编辑器生态、伤害公式、减伤率 75% 上限、最低保底 10%。

## 二、核心体验

v6 的体验重点从“我把装备摆对了吗”转为：

- 这局我的三个单位分别拿到什么主动技能？
- 这件防具要开新流派，还是喂给已有流派升 Lv？
- 这个流派是该给主核，还是给副核开第二机制？
- 满槽时，我愿意放弃哪一个机制？
- 遗物三选一，是补队伍短板，还是强化主流派？
- 魂栈买到老虎机遗物，是继续压低 roll 成本，还是赌高品质与流派？
- 英灵殿该献祭谁、把数值加给谁？被赋能单位不能转职，是否值得？

玩家不再做算术题。每个选择都有一句话后果预览：

```text
给剑士 → 觉醒烈焰（攻击附带灼烧）
给守卫 → 并入烈焰 Lv2
给法师 → 新增守护反弹（主流派仍烈焰）
```

装备仍是 build 核心，但它的价值表达从“+10% 攻击”变成“这单位从此会灼烧 / 反弹 / 击杀回魂火”。

## 三、核心循环

### 3.1 开局循环

```text
选择 3 个单位
  → 生成主动技能轮盘池
  → 转 3 次（玩家点开始 / 停止选技能）
  → 点单位落位
  → 进入地图
```

- roll 池 = 全技能通用（v6.66：主动技能不绑定单位；费用3技能按单位阈值过滤，阈值3快爆单位不出现费用3技能）。
- 3 次 roll 不重复同一技能 ID。
- ★ v6.68c：开局技能 roll 提供唯一 1 次免费重掷（二选一确认框），防具 roll 不提供重掷、停轮后直接落位。
- 不兼容单位灰显并说明原因。
- 点击单位即锁定，不能互换、不能撤销。
- 转职后获得第 2 格技能词条，固定内容、灰显不可操作。
- **转职触发（v6.54 确认）**：无等级门槛。Boss 战后进入英灵殿（CHAPEL）即可转职，免费；不为转职设"5 级"等等级条件——等级只影响属性，不 gate 构筑身份。

**单位特质层：基础魂火技能（v6.71，固定不 roll）**

> 旧表「按单位列可 roll 技能 / 任意 3 单位并集最小 3 个技能」是 v6.66 前口径，已废止。v6.66 起技能全通用，v6.71 起每个单位另有一个**固定的基础魂火技能**常驻唯一技能位，开局 roll 只做强化/替换。

| 单位 | 基础普攻特质 | 基础魂火技能（固定，费用+冷却） | 流派倾向（v6.72 纯提示，不加 Lv） |
|---|---|---|---|
| 剑士 swordsman | 近战单体稳定 | 冲锋 | 献祭 |
| 枪兵 spearman | 近战直线，可戳第二目标 | 贯穿 | 余烬 |
| 重甲 armored | 近战单体，慢但硬 | 嘲讽 | 守护 |
| 斧手 axeman | 近战高伤，低命中 | 蓄力斩 | 献祭 |
| 弓手 archer | 远程单体 | 狙击 | 余烬 |
| 飞马 pegasus | 高机动近战 | 俯冲 | 灰烬 |
| 法师 mage | 远程法术单体 | 火球 | 烈焰 |
| 牧师 cleric | 低攻近战/远程 | 群体治愈 | 轮回 |
| 龙裔 dragonborn | 近战/中程 | 龙息 | 灰烬 |

基础魂火技能带费用 2~3 与冷却，释放需魂火够 + 冷却就绪；roll 到的模板按 `anchor` 强化或替换它，不新增按钮。末列「流派倾向」只用于 roll 卡方向提示与软保底，**v6.72 起不再给该流派加 Lv**（共鸣已删除）。详见 5.0.0 / 5.3。

### 3.2 战斗循环

微循环仍是魂火状态管理：

```text
接敌 → 命中 +1 魂火 → 燃烧 / 正常（归零标“熄”）切换 → 技能与普攻取舍
```

击杀敌人即时获得经验（按敌人强度，唯一来源），满足阈值即自动升级（带 0.25s 停顿 + 白色 LV 跳字 + 音效的仪式感）。玩家不再在装备界面花金币手动升级单位。详见 5.7。

### 3.3 战后循环

```text
战斗胜利（击杀即判胜，信号在 HP 归零帧末发出）
  → 等待全部表演收尾 + 缓冲（v6.60，见 5.8）
  → 结算金币 / 魂 / 解锁
  → 防具轮盘（金币，玩家停轮选结果，每次 +50G）
  → 停轮后停留 0.5s 展示抽到的防具（期间不可操作）
  → 落袋界面：装备 / 并入 / 转向 / 放弃
  → 继续地图
```

战后结算不再出现防具卡片，不再有稀有防具掉落。胜利界面（v6.60）会先等 2 帧让击杀触发的攻击链启动，再等到**所有表演标志清空**——整条攻击链 `is_performing_action`（覆盖 Boss 死亡对话、死亡动画 0.58s）、获得物品弹窗、升级跳字计数、淡入淡出——最后再留 **0.4 秒真实时间缓冲**（不受倍速），节奏不急促；战后经验升级的跳字在弹面板前会再等一次。8 秒超时兜底防止标志残留卡死。这样避免"已判胜但面板在表演前就弹出/节奏太快"。防具轮盘停轮后固定停留 0.5 秒真实时间（不受倍速影响）展示结果，让玩家看清抽到了什么。

## 五、核心系统详解

## 五、核心系统详解

### 5.0 一句话体系：一次攻击两个选择（v6.63 定稿，v6.71 技能池三层重构）

> **一次攻击只有两个选择，所以技能按钮只能有一个；技能按钮只有一个，所以技能词条必须是“1 主动 + 1 被动”，转职不能给第二个主动；技能按钮唯一，所以魂火爆发不能另设按钮，只能并入技能按钮——魂火达到单位阈值（v6.66 快爆3/中节奏4/慢攒5）时自动爆发。三者不是三个独立改动，而是同一条决策链上的三个咬合点。**

#### 5.0.0 技能池三层（v6.71，取代旧「开局 roll 一个主动技能」口径）

技能系统分三层，**唯一技能位**的内容由前两层决定，第三层只改规则不占按钮：

| 层 | 内容 | 进 roll 池 | 占按钮 | 写档 |
|---|---|---|---|---|
| **特质层** | 单位自带固定普攻 + 固定**基础魂火技能**（9 单位各一，带费用 2~3 + 冷却） | ❌ | 普攻 + 技能各一（基础技能是技能位默认内容） | ✅ 固定 |
| **初始 roll 层** | 强化/替换模板（`anchor` = `basic_attack` / `soul_skill` / `both`），全模板通用池、按单位类型适配 | ✅ 唯一来源 | ❌ 不新增；`soul_skill` 替换技能位内容，`basic_attack` 记为普攻被动强化 | ✅ 锁定 |
| **转职身份层** | 代码现有转职分支改造：燃烧态/爆发特质、被动词条、主动降残响 | ❌ | ❌ 不新增 | 转职写档，残响不写档 |

- **基础魂火技能**：`unit_data.json.base_soul_skill` 给 9 单位各配一个（剑士冲锋、枪兵贯穿、重甲嘲讽、斧手蓄力斩、弓手狙击、飞马俯冲、法师火球、牧师群体治愈、龙裔龙息），开局常驻 `talent_slots[0]`（`is_base=true`，配装界面不可手改，但可被引擎/roll 替换）。
- **初始 roll 3 次不重复**：`anchor=soul_skill` → 替换基础魂火技能；`anchor=basic_attack` → 记入 `basic_enhancements` 作普攻被动强化（只吃 `damage_mult`，不占按钮、不耗魂、不进冷却）；`anchor=both` → 两者都做。落位后该单位本次 roll 机会用尽。
- **换掉了什么**：v6.34/v6.69 的 **Build 觉醒技（消费 6 魂火的全场质变）已删除**——流派全场质变改由「魂火爆发（burst_requested）+ 单位/转职身份 `burst_trait`」接管；防具 build 回归被动机制层（六流派 Lv1~4；v6.72 起共鸣已删，等级只由防具决定）。攻击菜单仍是普攻/技能两项，不因此变多。
- **单位差异不重叠**：特质层管「技能位默认内容」，身份层 `burn_trait`/`burst_trait` 管「自动结算的燃烧/爆发质变」，两者不叠加、不互相覆盖。

#### 5.0.1 体系因果链

```text
每回合一次攻击
→ 只允许两个指令：普攻 / 技能
→ 技能按钮必须唯一，不能有第二个主动按钮、不能长按、不能切换
→ 技能词条固定 1 主动 + 1 转职被动，转职不再给第二个主动
→ 魂火爆发不能是独立按钮，只能并入技能按钮：魂火达单位阈值自动爆发（v6.66 身份化）
→ 魂火只剩两态：燃烧（保留魂火的收益）/ 正常（无增益，归零不补负面）
→ 玩家每回合只做一个决策：普攻保魂火维持燃烧，还是技能花魂火（可能自动爆发）
```

这条链上任何一环松动，另外两环就会回退：

- 如果允许转职给第二个主动 → 技能按钮必然要分裂成两个 → "一次攻击两个选择"破产；
- 如果魂火爆发保留独立按钮 → 攻击区出现第三个按钮 → 同样破产；
- 如果魂火保留"枯竭"负面/增益 → 玩家要同时管理"燃烧/正常/枯竭"三态 + 爆发 → 决策重新变复杂。

所以三者必须一起定稿。

#### 5.0.2 三个子系统的咬合点

**1. 攻击手段：两个指令**

| | 普攻 | 技能 |
|---|---|---|
| 消耗 | 无 | 2~3 魂火；魂火达单位阈值自动爆发（费用3技能仅配阈值≥4单位） |
| 回魂火 | 命中 +1 | 命中 +1 |
| 燃烧增益 | 吃燃烧态溅射 50% | 吃燃烧强化溅射 |
| 触发被动 | 是 | 是 |
| 定位 | 保魂火、维持燃烧、稳定触发 | 花魂火、强化伤害、改变节奏 |

所有被动——烈焰追加、异常施加/消费、追击、溅射、反击、余烬必暴、击杀钩子——**自动结算，不占按钮、不弹选择**。只有普攻和技能能施加/消费异常；追击、溅射、反击只算附加伤害，避免连锁。

**2. 技能词条：1 主动 + 1 被动**

| 槽位 | 类型 | 来源 | 是否增加攻击按钮 |
|---|---|---|---|
| 第 1 格 | 主动技能词条 | 开局 roll，锁定 | 是，技能按钮唯一来源 |
| 第 2 格 | 转职被动词条 | 转职固定，锁定灰显 | 否，只改规则/触发 |

转职被动只做三类：强化型（强化已有主动）、触发型（自动触发）、改造型（改造原主动）。**禁止转职再给一个主动攻击技能。**

若某分支必须替换主动，旧主动转“残响被动”：只保留流派标签 + 一个小自动效果，不占按钮、不可切换、不升级、不写存档；转职面板必须明示。更推荐转职只做“改造”，从根上避免覆盖。

未转职单位最多 1 个主动技能词条；候选池不是“已拥有技能”，战斗指令/流派机制/遗物/转职被动都不算技能词条。

**3. 魂火：两态 + 技能自动爆发**

| 状态 | 触发 | 效果 |
|---|---|---|
| 燃烧 | 魂火 > 50% 上限 | 移动 +1，普攻/技能溅射 50% |
| 正常 | 0%–50% | 无；归零 HUD 标“熄”，不补负面 |

技能按钮唯一行为：

| 释放时魂火 | 结算 | 消耗 |
|---|---|---|
| < 技能费用 | 不可用，灰显 | — |
| ≥ 费用，<3 | 普通释放 | 2~3 |
| ≥3 | **自动爆发**，强制暴击 + 额外伤害，结束行动 | 全部魂火 |

没有独立爆发按钮，没有长按，没有切换。燃烧态只增益普攻/技能与移动，不再和爆发并列。爆发伤害可按消耗魂火数缩放，封顶在魂火上限的 50%。

#### 5.0.3 玩家一个回合的实际体验

```text
1. 选目标
2. 看技能按钮：
- 魂火不足 → 按钮灰显
- 魂火 2~3 → “技能：消耗 2 魂火”
- 魂火达单位阈值 → “技能·身份爆发文案”（不写当前魂火，见下方阈值口径）
3. 二选一：
- 点普攻 → 无消耗，命中回 1 魂火，燃烧态带溅射，自动触发被动
- 点技能 → 按魂火自动普通/爆发，自动触发被动
4. 自动结算：伤害 → 回魂火 → 异常施加/消费 → 烈焰追加 → 溅射 → 追击 → 击杀钩子 → 反击
5. 回合结束
```

玩家每回合只回答一个问题：**这回合是普攻保魂火维持燃烧，还是放技能把魂火花掉（可能自动爆发）？**

#### 5.0.4 数据与 UI 的统一出口

| 层 | 统一出口 | 禁止 |
|---|---|---|
| 攻击指令 | 普攻 / 技能两个按钮 | 第三个攻击按钮、长按、切换、独立爆发按钮 |
| 技能词条 | `skill_type = active / passive`；slot0 active，slot1 passive | 转职给第二个 active；第 2 格可切换 |
| 魂火消耗 | 只有技能按钮一个入口 | 独立爆发入口；枯竭态负面/增益 |
| 异常 | 只由普攻/技能触发施加/消费 | 追击/溅射/反击触发异常；异常独立按钮 |
| 被动 | 自动结算，攻击预览一句话显示 | 被动列成技能按钮；被动弹选择 |

#### 5.0.5 最终口径表

| 主题 | 定稿口径 |
|---|---|
| 攻击手段 | 一次攻击只有 **普攻 / 技能** 两个选择；被动全部自动结算 |
| 技能词条 | **1 主动 + 1 转职被动**；转职不再给第二个主动攻击技能；必须替换时旧主动转残响被动 |
| 魂火状态 | **两态**：燃烧（>50%，移动+1、溅射50%）/ 正常（无增益，归零不补负面） |
| 魂火爆发 | **并入技能按钮**：魂火达**单位阈值**（v6.66：快爆3/中节奏4/慢攒5）时技能自动爆发，清空魂火，强制暴击 + 额外伤害，结束行动 |
| 魂火决策 | 每回合只选：普攻保魂火维持燃烧，还是技能花魂火（可能自动爆发） |
| 异常状态 | 合入防具词条；施加给全队易伤，消费引发大量伤害/特殊效果；只由普攻/技能触发 |
| 转职 | 只给被动，不增加攻击按钮；不 gate 等级，免费 |
| UI | 两个攻击按钮；技能按钮上标注“消耗 N”或“将爆发”；无长按、无切换、无独立爆发按钮 |

#### 5.0.6 一句话总结

> **“一次攻击两个选择”是目标，“1 主动 + 1 被动”是词条结构对目标的保证，“魂火两态 + 技能自动爆发”是魂火系统对目标的让路。三者共同把每回合的决策压缩成一句话：普攻保魂火维持燃烧，还是技能花魂火（可能自动爆发）。这就是一个体系。**

### 5.1 魂火系统

魂火仍是一个数值、三重身份：

| 身份 | 表现 |
|---|---|
| 资源 | 主动技能（含自动爆发）、破盾等消耗 |
| 状态 | 燃烧 / 正常；归零并入正常并 HUD 标记“熄” |
| 续航 | 战后 100% 写回持久层，跨节点继承 |

两态：

| 状态 | 触发 | 效果 |
|---|---|---|
| 燃烧 | > 50% 上限 | 移动 +1，攻击溅射 50% |
| 正常 | 0%–50% | 无 |

规则说明：

- **低魂火 / 归零不是“枯竭”负面状态，也不提供额外增益。** 它只是“没有燃烧增益”的正常状态；HUD 在魂火归零时标记“熄”，提示玩家已失去燃烧增益。
- 魂火张力来自“消耗魂火换技能/爆发”与“保留魂火维持燃烧”的取舍，而不是低魂火惩罚或低魂火奖励。
- 余烬流派的“魂火耗尽时下一次攻击必暴”是该流派自身的机制，不是通用状态；它让“主动打空魂火”成为余烬 build 的选择，而不是全职业的低魂火收益。
- 魂火爆发（≥3 魂火消耗全部）仍是“清空魂火换一次强击”的主动取舍，使用后失去燃烧增益，符合两态设计。

获得口径：

- 命中 +1，包含普攻、追击、溅射、AOE、反击等命中结算。
- 我方单位阵亡 +5。
- 归零态击杀 +1，帮助重新进入燃烧（不是负面补偿，只是低魂火时的微量回补）。
- 装备 / 遗物 / 流派机制的击杀回魂火钩子按新机制结算。
- 战斗奖励发放“魂”，不发放魂火。

主动技能消耗必须在释放瞬间前扣，并显示“消耗 N 魂火”；命中 / 击杀收益在之后结算，避免净变化看起来为零。

**魂火技能冷却规则（v6.71）**：所有消耗魂火的技能（单位基础魂火技能、被 roll 强化/替换后的技能按钮内容）释放需**同时满足**「魂火 ≥ 费用」与「冷却就绪」；释放后立即按其 `cooldown` 进入冷却（按回合递减），冷却期间技能位灰显、普攻仍可用；冷却结束且魂火足够即可再次释放。费用与冷却都写在 `talents.json`（新字段 `cost`/`cooldown`，兼容旧 `effect_params.soul_fire_cost`/`cooldown_after_trigger`），不硬编码。**普攻无消耗无冷却**；魂火爆发是本次技能释放的强化形态，不单独设冷却、不额外延长技能冷却。
- **冷却生效审计（v6.72）**：主线战场/竞技场的释放→写冷却（`TalentManager.reset_talent`）→每回合递减（`accumulate_talents`，我/敌/竞技三路齐全）→归零恢复就绪，闭环**真实生效**。真实冷却 = `cooldown - cooldown_reduction`（冲锋 2-1=1、狙击 2、嘲讽 3、速射 1-1=0）。本轮修复：① `reset_talent`/`_get_active_skill_cost` 此前只读旧字段，已改为**优先读新 `cooldown`/`cost`**（否则 v6.71 迁移的字段是死代码）；② Boss 变形复活此前会清空冷却，已改为按技能 id 保留旧冷却；③ 主动治疗此前只在 `mass_heal_percent>0` 分支写冷却，已改为付费成功即写。仍存低优先级项：局外存档不保存战斗冷却（重进战斗技能满就绪，属设计结果）；`cooldown_remaining>=9999` 永久冷却特判只用于被动词条。

魂火爆发（v6.63）：不再有独立按钮——≥3 魂火时释放技能即自动爆发，消耗全部魂火、强制暴击并附加额外伤害，使用后强制结束行动。详见 5.0。

### 5.2 流派与标签

6 个流派：烈焰 / 轮回 / 灰烬 / 守护 / 献祭 / 余烬。单位不再预设流派，流派身份每局由玩家选择形成。

| 流派 | 机制 | 战斗接线点 | Lv1 / Lv2 / Lv3 / Lv4 |
|---|---|---|---|
| 烈焰 | 攻击附带灼烧，可叠层 | `CombatManager._apply_damage_with_effects` | 本次伤害 15% / 25% / 35% / 45% 追加无视减伤伤害 |
| 守护 | 受击反弹伤害；格挡触发时翻倍 | `CombatManager._apply_damage_with_effects` | 反弹 30% / 45% / 60% / 75%，格挡当次 ×2 |
| 轮回 | 击杀回魂火（与命中 +1 分开结算） | `CombatManager._on_kill` | 额外 +2 / +3 / +4 / +5 魂火；Lv2 起击杀额外治疗最低血队友 8% HP |
| 献祭 | 每回合扣血换本回合攻击 | `TurnManager._apply_school_turn_start` | 扣 3% / 4% / 5% / 6% HP（保底 1 HP），攻击 +10% / 15% / 20% / 25% |
| 灰烬 | 移动后从起点留下燃烧地块 | `Battlefield` 移动完成 → `CombatManager.drop/trigger_ash_tile` | 踩中受 3 / 5 / 7 / 9 伤害，活到下一次我方回合，场上最多 12 块 |
| 余烬 | 魂火耗尽时下一次攻击必暴 | `CombatManager.execute_attack` 暴击链 | 必暴并追加暴伤 +10% / +20% / +30% / +40%，魂火恢复后重新装填 |

具体数值可调，但原则是：**一件即完整生效、一句话能说清、穿上就改变打法**。所有机制都读 `BuildManager.get_effective_school_level(unit, school)`，不再各自解析防具。

**Build 配合的方向：单位之间，而非单单位多流派。** Build 的深度来自"队伍里谁穿什么流派、彼此怎么互补"——例如守护单位在前排反弹、轮回单位在后方击杀回魂火、灰烬单位封走位制造地形。一个单位原则上只追求**一个主流派升到高 Lv**（机制槽允许临时挂第二流派，但那是应急而非构筑目标）。因此**不设"同单位双流派组合技"**：v6.34 曾实验的 `BuildManager.SYNERGIES`（野火/血祭/背水/收割/焚身五个单单位双流派联动）已于 v6.36 移除——它与上述方向相反，且只有数据层与竞技场简化数值、主线战场从未接线，属于半成品。

**单位间配合已移除（v6.59）**：v6.37 曾在 `FormationManager` 实现六组站位阵型配合（F1 燎原 / F2 铁壁护卫 / F3 轮回链 / F4 血祭传递 / F5 余烬引爆 / F6 灰烬火墙），靠格子相邻触发。因理解成本过高，v6.59 已整套移除——包括效果触发、彩色连线、详情面板「阵型:」行与相关信号；`FormationManager` 从 autoload 移除并置为空壳。现在的 build 深度**只来自单单位流派选择**（上表六流派各自的机制），不再有"谁站谁旁边"的隐藏规则。`docs/TeamSynergyDesign.md` 已作废，仅留档。

技能上限：每单位 2 格（v6.63 体系定稿：**1 主动 + 1 被动**，见 5.0）。

| 格位 | 来源 | 规则 |
|---|---|---|
| 第 1 格 | 单位基础魂火技能 → 开局 roll 强化/替换 | **v6.71**：开局常驻单位固定基础魂火技能（`is_base=true`，配装界面不可手改）；3 次 roll 按 `anchor` 替换它（`soul_skill`）或记为普攻被动强化（`basic_attack`，不占按钮） |

- 两格技能词条都不可互换、不可重洗、不可覆盖；基础魂火技能不可被配装移除，但可被引擎/roll 替换。
- 选定离手；装备界面只展示，不操作。
- 主动技能释放时显示魂火消耗与冷却（同时满足魂火≥费用 + 冷却就绪才可释放）。
- **通用轮盘老虎机（v6.3）**：开局技能与战后防具 roll 都改成「玩家点开始 → 看准图标点停」的转轮，带加速/减速过程；结果与停止时机绑定，**玩家选而不是系统直接给**。轮盘组件 `SlotMachineUI.gd` 可复用，**纵向只显示上一条 / 当前 / 下一条三行（图标 + 技能名），当前行金色高亮；右侧同一个按钮空闲时是开始、旋转时是停止，停轮后禁用、不再提供「再来一次」**；转轮用真实时间推进，不受游戏倍速影响，且节奏放慢（启动 0.16s  gradually→0.085s，停止后 8 格减速）。技能轮盘池（v6.71）为**全模板通用池**：17 个主动技能全部开放给 9 单位，`compatible_units` 不再决定池子（旧「并集 / 单技能兼容 3~5 单位 / 群体治愈仅 cleric」口径已废止），费用 3 技能按单位爆发阈值过滤；按「剩余单位是否仍能 roll」软过滤，确保停到的技能有可落位单位；群体治愈等技能按 `unit_type_scaling` 在不同单位上给不同收益（低收益单位提示但不禁止）。防具轮盘池为当前品质权重下抽出的 8 件候选防具。**停轮后停留 0.5 秒真实时间展示抽到的防具（v6.58）**，期间全程锁定不可操作，之后才进入落袋界面——解决"还没看清抽到什么就被切走"的问题。
- **共鸣已删除（v6.72）**：旧版「主动技能带流派标签 → 该流派有效 Lv +1（上限 4）」的机制整套移除。现在**流派 Lv 只由防具机制决定**（Lv1~4），技能不再加 Lv。
  - 战斗层 `BuildManager.get_effective_school_level()` 函数壳保留（几十处调用点无需改），语义简化为「直接返回防具机制 Lv」；数值函数封顶常量 `RESONANCE_MAX_LEVEL` 改名 `SCHOOL_MECH_MAX_LEVEL`（仅作 Lv 上限，与共鸣无关）。

  - 删除理由（v6.71b 审计）：共鸣最大价值在「Lv1 防具即跨质变线」，但理解成本高、且 v6.71 后 9 单位基础技能全带标签导致"穿对应防具自动共鸣"近乎常驻，随机性与决策价值都变弱。一并删除后 build 更直白：**想要高流派 Lv 就堆同流派防具**。
  - 一并删除的「每日祝福」（旧称火焰共鸣 / `LevelManager.current_resonance`）：按天全队 roll 的战场祝福（攻击 +5%、魂火上限 +1、暴伤 +10% 等），与装备 build 无关，现已整套移除——含魂火上限/初始值加成、战斗 buff、地图 HUD 的 ResonanceLabel 节点。

### 5.4 防具与机制槽（v6.53 重构：词条即流派）

防具的角色被明确拆成两层：**防具承担基础数值，词条承担流派**。

```text
流派身份 = 该防具词条 tags 中的流派（按 SCHOOL_ORDER 取优先级）
已用机制槽数 = 单位当前觉醒的不同流派数
某流派 Lv   = 该流派累积的同流派防具贡献（受品质 cap 限制）
```

**核心变更（v6.53）**：流派不再由 `ItemData.tags` 判定，改由词条 tags 判定（`BuildManager.get_school_of_affixes`）。转轮 roll 时就生成词条（`roll_armor` 的 `entry.affixes`）并一路带到落位实例——修复了旧链路"落位防具词条为空"的问题。16 个词条全部带流派 tag（原唯一通用的"锋锐"归入烈焰）。

**落位三动作**（统一在 ConfirmUI 双选项面板 `show_choice` 中决策，见 5.5）：

| 动作 | 规则 | 玩家收益 |
|---|---|---|
| 强化（并入） | 同流派机制 Lv+1；**不 append 实例、不改已有词条** | 流派变强，已配好的词条与搭配完全不变 |
| 觉醒 | 空格遇到新流派 → 直接觉醒 Lv1，不弹面板 | 纯增益无取舍，不打断节奏 |
| 转向（置换） | 替换玩家点击的那个防具槽的流派，**100% 继承**旧流派 Lv/cap/count，新防具词条落到该槽 | 换 build 方向不归零，等级词条都带走 |

旧版"覆盖"（删光旧流派、新流派从 Lv1 重来、词条全清）已废弃；`overwrite_at_slot` 实现转向。机制上限仍为 common 2 / rare 3 / epic 4 / legendary 4。

**专精防具（v6.54）**：`ItemData.affix_schools` 可选字段——空=词条流派跟随防具 tags；非空=只允许该池流派的词条（`AffixManager.roll_affixes` 第三参数）。判定用方案 A：多 tag 词条（如灰烬护体带灰烬+守护）优先按防具锁定池归属，避免方向冲突。编辑器（`JSONEditorPanel`）用六流派下拉 + 增删按钮编辑此字段。**当前 50 件防具该字段均为空，功能已就绪但未启用数据。**

其余规则沿用：不同流派开新槽（受单位 1/2/3 槽限制，过天 +1 上限 4）；词条出生即定、只读、不可互换（16 条，品质挂 1/2/2/3 条）；方向/连通组/单位换位已从玩家层移除。展示口径见 `docs/ArmorSimplificationDiscussion.md`。

单位机制槽名单：

| 槽数 | 单位 | 理由 |
|---|---|---|
| 1 槽 | armored、dragonborn | 本体强，单机制专精 |
| 2 槽 | spearman、pegasus、archer、axeman、cleric | 大部分单位，主流派 + 副流派 |
| 3 槽 | swordsman、mage | 多分支成长，靠多机制差异化 |

### 5.4.1 异常状态合入词条（v6.62y 已落地）

> ✅ **v6.62y 已落地**（静态校验，待实机验证）。异常状态完全由防具词条承载，不新增系统层/第七流派。核心逻辑集中在 `AbnormalManager.gd`（`class_name` 静态类），数据挂 `Unit.abnormal_stacks`（战斗内临时、不写存档）。以下按「一条核心机制 → 三层效果 → 三条链路 → 数值口径 → 交互 → 落地顺序」整理，并附实现与偏差。

#### 一、核心机制

> **施加流派给敌方上异常层 → 异常层本身是"全队易伤标记"，任何伤害都有小幅增益 → 消费流派攻击带异常目标时，引发大量伤害或特殊效果，并清层。**

这条机制同时解决三件事：

1. **施加流派有团队价值**：不是只有消费流派受益，全队打带异常目标都多打一点。
2. **消费流派有爆发窗口**：不是"上个状态就完事"，而是"等层数叠起来再打"。
3. **异常状态不是私密配合**：A 上状态、B 消费、C 也能吃到易伤，队伍之间有时序配合，但不需要站位、不需要同单位双流派。

由此把"基础链路归流派、词条做增强"彻底修正为：**异常状态完全由词条承载，词条分"施加词条"和"消费词条"两类；异常层数本身是通用易伤，消费是词条专属爆发。**

#### 二、三层效果，各司其职

| 层 | 效果 | 受益者 | 幅度 | 是否清层 |
|---|---|---|---|---|
| 施加层 | 词条让攻击/受击/移动时给敌方上 1 层异常，最多 3 层，持续 2 回合 | 施加者 | 概率/层数随词条品质和流派 Lv 缩放 | 否 |
| **易伤层** | **每层使目标受到的所有伤害 +3%（灰烬 +2%），最多 3 层（+9% / +6%）** | **全队任何伤害来源** | 小幅、通用 | 否 |
| 消费层 | 消费词条持有者攻击带异常目标时，引爆/融化/汲取所有层 | 消费流派 | 大幅、专属 | 是（清空该异常层） |

关键边界：

- **易伤层对所有伤害生效**：普攻、技能、DOT、反击、溅射、灰烬地块都吃（统一走 `CombatManager.calculate_damage` 与 `AbnormalManager.tick_dot`）。这样施加流派不是"给消费流派打工"，而是给全队加易伤标记。
- **易伤幅度必须小**：每层 2~3%，3 层 6~9%。太大变"必带异常"，太小玩家感知不到。
- **消费是词条专属，不是流派自带**：没有消费词条，异常层只提供易伤；有消费词条，才有爆发窗口。
- **消费后清层**：形成"施加 → 叠层 → 消费 → 再施加"的循环；消费伤害按层数计算，3 层收益最高（legendary 引爆每场 1 次不耗层例外）。
- **异常不写存档、不占机制槽、不改变单位/等级数据**，只是词条在战斗内的临时产物。

#### 三、异常类型与流派配对：每种异常只做"1 施加 + 1 消费"

不新增冰冻流派，冰冻只是异常类型之一。先做 2 种，跑通后加第 3 种。每种异常只绑定一对流派，不做六流派反应表。

**链路 A：灼烧（烈焰施加 → 余烬消费）**

| 项 | 内容 |
|---|---|
| 施加词条 | **灼热之刃**（烈焰 tag） |
| 施加方式 | 攻击时概率上 1 层灼烧，最多 3 层，持续 2 回合；概率随词条品质和烈焰有效 Lv 缩放 |
| 易伤 | 每层目标受到的所有伤害 +3%，3 层 +9% |
| 消费词条 | **引爆专精**（余烬 tag） |
| 消费效果 | 余烬攻击带灼烧目标时引爆所有层：每层造成施加者攻击 12% 的伤害，3 层 = 36% 攻击的爆发；清空灼烧 |
| 特殊效果（epic+） | 引爆后目标禁疗 1 回合；legendary 每场首次引爆不耗层 |
| 一句话 | **"烈焰上灼烧，全队打得更疼；余烬引爆，一次结算大量伤害。"** |

**链路 B：冻寒（守护施加 → 烈焰消费）**

| 项 | 内容 |
|---|---|
| 施加词条 | **寒霜护甲**（守护 tag） |
| 施加方式 | 受击时概率给攻击者上 1 层冻寒，最多 3 层，持续 2 回合 |
| 易伤 | 每层目标受到的所有伤害 +3%，移动 -1（最多 -2），**不跳过行动** |
| 消费词条 | **融雪**（烈焰 tag） |
| 消费效果 | 烈焰攻击带冻寒目标时融化所有层：每层造成攻击 10% 的伤害，3 层 = 30%；清空冻寒 |

**链路 C（跑通 A/B 后加）：灰烬附着（灰烬施加 → 轮回消费）**

| 项 | 内容 |

#### 四、与防具词条的关系：施加、消费、普通三类

合入词条后，词条分三类，但**不增加词条数量**（仍是 1/2/2/3 条）：

| 词条类型 | 作用 | 例子 | 是否带流派 tag |
|---|---|---|---|
| 普通词条 | 纯数值 | 锋锐、坚韧、迅捷 | 是（烈焰/守护等） |
| 施加词条 | 数值 + 给敌方上异常 | 灼热之刃、寒霜护甲、余烬足迹 | 是（施加流派） |
| 消费词条 | 数值 + 引爆/特殊效果 | 引爆专精、融雪、魂火汲取 | 是（消费流派） |

规则：

- 施加词条和消费词条**仍参与流派身份判定**，按六流派 tag 归入对应机制槽，不新增第七流派。
- 异常类型是词条的**子属性**，不参与 `SCHOOL_ORDER` 判定；多 tag 词条按防具锁定池归属。
- **品质决定强度**，不决定是否存在：common 也能施加/消费，只是概率低、无特殊效果；legendary 概率高、带禁疗/减速/额外治疗等特殊效果。
- **异常强度随流派有效 Lv 缩放**：施加概率 = 基础概率 + 流派 Lv×5%；消费伤害 = 基础 + 流派 Lv×2%。这样强化同流派升 Lv 时，异常 build 也跟着成长，解决"强化不 append 实例、不改词条"导致异常成长脱节的问题。
- **专精防具**（`affix_schools`）有数据意义：烈焰专精只出烈焰词条（含灼热之刃/融雪）、余烬专精只出引爆专精、守护专精只出寒霜护甲、轮回专精只出魂火汲取、灰烬专精只出余烬足迹。

品质分级：

| 词条 | common | rare | epic | legendary |
|---|---|---|---|---|
| 灼热之刃（烈焰） | 25% 上 1 层 | 35% | 45%，上限 +1 | 55%，施加时立即跳一次易伤 |
| 引爆专精（余烬） | 引爆伤害 +25% | +50% | +75%，禁疗 1 回合 | +100%，引爆不耗层（每场 1 次） |
| 寒霜护甲（守护） | 25% 上 1 层 | 35% | 45%，冻寒易伤 +2%/层 | 55%，冻寒上限 +1 |
| 融雪（烈焰） | 融化伤害 +25% | +50% | +75%，减速 2 回合 | +100%，融化后刷新 1 层灼烧 |
| 余烬足迹（灰烬） | 50% 附着 | 75% | 100% | 100%，附着上限 +1 |
| 魂火汲取（轮回） | 每层回 1 魂火 | 每层回 1 魂火 + 治疗 3% | 治疗 5% | 治疗 7%，额外治疗 1 次 |

#### 五、数值口径：易伤小、消费大、层数封顶

| 项 | 建议值 | 理由 |
|---|---|---|
| 异常层数上限 | 3 层（epic/legendary 变体 +1） | 易伤最高 +9%，消费最高 3 层收益，玩家好算 |
| 持续时间 | 2 回合，刷新不叠加 | 短战斗能感知，长战斗不会永久挂着 |
| 易伤幅度 | 灼烧/冻寒 +3%/层，灰烬 +2%/层 | 全队受益，但不足以让异常变成必带 |
| 消费伤害 | 灼烧 12%/层、冻寒 10%/层攻击 | 3 层 = 30~36% 攻击的爆发，明显高于一次普攻 |
| 消费特殊效果 | epic 起给禁疗/减速/回魂火/治疗 | 避免硬控；特殊效果是"锦上添花"，不是"唯一价值" |
| 施加概率 | 25~55%，随品质和流派 Lv | common 也能上，legendary 更稳 |
| DOT/消费击杀归属 | DOT 归施加者，消费归消费流派 | 正常触发轮回回魂火、击杀经验、掉落 |
| Boss 多形态 | 阶段切换清空异常或只保留 1 层 | 避免 DOT 跳过阶段；DOT 跳死复用 v6.57 判胜 |
| 竞技场 | 只保留灼烧+引爆；冻寒只减速不硬控；灰烬 1v1 不触发 | 保持 1v1 节奏 |

这样"施加流派 + 任何伤害小幅增益"成立，但不会让异常变成唯一解；"消费流派 + 大量伤害/特殊效果"成立，但不会让消费流派变成必带。

#### 六、与现有系统的交互

1. **词条即流派**：施加/消费词条仍带六流派 tag，机制槽、流派 Lv（v6.72 起只由防具决定，共鸣已删）全部不变；异常类型是子属性，不参与流派判定。
2. **强化与异常成长**：强化不 append 实例、不改词条，所以异常强度按流派有效 Lv 缩放，否则专精主流派不会让异常变强。
3. **转向刷词条**：转向 100% 继承等级且新词条落到该槽，可能被用来反复刷异常词条。建议转向后本场战斗不能再转向，或转向消耗金币。
4. **轮回**：DOT 击杀归施加者，正常触发轮回回魂火/治疗；魂火汲取消费词条让轮回也能主动吃异常，缓解"cleric 抢不到击杀"。
5. **献祭**：不新增异常，作为"对带异常目标额外 +5% 攻击"的收益者，避免一次铺太大。
6. **自动战斗**：识别"带异常且层数 ≥2 的目标优先消费流派攻击"，否则托管下消费链路无效。
7. **经济**：异常词条不解决金币紧、强化封顶浪费；这两项 v6.62z 已做规则调整（首次 50G roll + 封顶退款/注入），异常词条仍按 P1 落地。

#### 七、落地顺序

1. 统一 cap 表（5.4 vs 6.3），明确强化/转向 cap 规则——异常词条品质分级的前提。
2. **先做灼烧一条链路**：改"灼热之刃""引爆专精"，配 1 件烈焰专精防具、1 件余烬专精防具；易伤 3%/层、消费 12%/层、3 层封顶。
3. **验证**：不抽异常词条时玩家是否仍理解流派机制；抽到施加词条是否感觉"全队打得更疼"；抽到消费词条是否感觉"叠层后引爆很爽"；专精防具是否让 build 可控；自动战斗是否乱引爆；DOT 击杀是否正常触发轮回/经验。
4. **再加冻寒→融化**：守护施加、烈焰消费，2 词条 + 专精防具。
5. **再加灰烬附着→魂火汲取**：灰烬施加、轮回消费，让灰烬后期不废、轮回有主动触发。
6. **最后调数值**：易伤小、消费大，差距控制在"没词条能玩，有词条爽"，避免异常变成必带。

#### 八、一句话总结

> **异常状态合入防具词条：施加词条给敌方上异常层，异常层本身是全队通用易伤（任何伤害小幅增益），消费词条攻击带异常目标时引发大量伤害或特殊效果并清层。每种异常只绑定"1 施加 + 1 消费"一对流派，先做灼烧（烈焰→余烬）、冻寒（守护→烈焰）、灰烬附着（灰烬→轮回）三条短链路；异常强度随流派 Lv 缩放，专精防具提供可控入口。这样等级管底盘、防具管数值、词条管身份与异常、技能管起点，五层分工不打架。**

### 5.4.2 转职 = 魂火身份升级（v6.64）

> **转职不爽，是因为它没碰魂火；魂火同质化，是因为燃烧态和爆发被做成了统一模板。** 把两者合起来解——让转职成为"魂火身份升级"，让每个单位的燃烧态增益和爆发形态都不同。这不破坏 v6.63 体系：爆发仍在技能按钮内、仍清空魂火、仍结束行动；转职仍只给被动、仍不增加按钮。**变的是"爆发的效果"和"燃烧态的增益"，不是"爆发的入口"。**

#### 一、设计原则

| 原则 | 内容 |
|---|---|
| 燃烧态 = 通用底盘 + 单位身份增益 | 保留"移动 +1、溅射 50%"通用底盘（玩家不用重学），每个单位额外一条燃烧态特有效果 |
| 爆发 = 技能爆发形态 | `爆发 = 原技能效果（保留功能） × 爆发倍率（强制暴击+额外伤害） + 单位特有爆发附加 + 清空魂火 + 结束行动`。原技能功能不再被 `soul_fire_burst` 替换丢失，治疗/坦克爆发也有形态 |
| 转职分支 = 魂火身份选择 | 每个分支定义燃烧态改造 / 爆发改造 / 一个被动词条 / 身份表现，转职变成"我的单位以后魂火怎么玩" |

|---|---|---|

| 飞马 | 移动 +2（替代 +1），可穿越敌方单位 | 机动游击 |
| 重甲 | 受击减伤 +15%、反弹 +30% | 前排反伤 |

| 剑士 | 相邻敌人 80% 攻击横扫 + 击退 1 格 | 冲锋变横扫，打完还推开 |

#### 五、落地优先级与风险

- **P0**：剑士/法师/牧师/重甲 4 样板，覆盖输出/法术/治疗/坦克；把爆发从"替换 skill_id"改成"技能爆发形态"（技术前提）。
- **P1**：转职分支绑定魂火身份（每单位先 2 分支），转职面板预告"转职后魂火变化"；身份表现（名号/色调/HUD图标/爆发文案/转职瞬间音效+定格）。
- **P2**：燃烧态增益全单位铺开；平衡与认知负荷（每单位燃烧态 1~2 条、爆发附加 1~2 条，HUD 图标 + 一句话 tooltip）。

风险：① 认知负荷——用 HUD 图标 + 技能按钮文案 + 转职面板预告 + 单位面板一句话缓解；② 平衡工作量——先样板、先 PvE、竞技场简化；③ 与流派正交——魂火身份由"单位 + 转职分支"决定，流派只提供额外 hook，两者叠加不互相依赖；④ 爆发强度——保留原技能 + 倍率 + 附加可能偏强，控制倍率、附加偏功能而非纯数值。

**出售返还率机制（v6.62k）**：出售价 = 遗物 `price` × 当前返还率，返还率 = `BASE_SELL_RATE(0.5)` + 已装备团队遗物的 `effects.relic_sell_rate_bonus` 之和（clamp 到 0~1，保底 1G）。基础 50%，装备交易遗物后 70%，多件同类遗物可继续叠加。逻辑在 `RelicShop.get_sell_rate()/get_relic_sell_price()`，出售区标签实时显示当前返还百分比。

**稀有度与掉率权重（v6.62r）**：每件遗物配 `rarity` 字段分三档——`common` 普通（权重 10）、`rare` 稀有（权重 4）、`epic` 史诗（权重 1），越稀有权重越低。22 件全部分级（10 common / 9 rare / 3 epic），团队池与老虎机池各有完整三档梯度。`RelicManager.weighted_pick(ids, count)` 用轮盘赌做**不放回加权抽取**（单件概率=权重/池权重和，抽走即移出池；池不足返回全部，权重和为 0 退化等概率）。魂栈商店（`RelicShop._roll_candidates`，各抽 3）与战后遗物三选一（`RelicSelectUI`，抽 3）均改用它，替代原等概率 `shuffle()`。实测占比：团队池 common 62% / rare 36% / epic 2%，老虎机池 common 56% / rare 34% / epic 10%。缺 `rarity` 字段按 common 处理（向后兼容）；编辑器遗物页提供中文下拉（普通/稀有/史诗）配置，新建遗物默认 common。

### 5.7 单位成长（v6.58 重做）

等级系统保留，成长原则：**自动为主，来源清晰，不制造额外操作**。

**经验来源**：

- **击杀得经验（唯一来源）**：我方单位击杀敌人时，按被击杀敌人的强度获得经验。每个敌方单位在 `unit_data.json` 配 `exp` 字段（普通兵 25~60，Boss 80~200），代码读到 `UnitData.kill_exp`（`exp` 是 GDScript 内置函数不能作变量名）。所有击杀路径（普攻 / 溅射 / 反击 / 追击 / 灰烬地块）都经 `CombatManager._on_kill` 统一结算，溅射等间接击杀也计入击杀者。竞技场同理（`ArenaBattle._arena_on_kill`）。
- **胜利后不再发经验（v6.61）**：旧的 `VictoryHandler` 按节点类型 + 评级发额外经验、`Arena.gd` 战后发经验均已移除，评级只影响金币/魂等战利品，不再折算经验。经验唯一来源就是击杀。
- 旧口径"击杀/伤害/治疗/存活都进经验条"从未在代码实现，v6.58 起以击杀为准，v6.61 移除战后额外后更加纯粹。

**升级规则**：

- 经验满足阈值即自动升级，`BuildManager.exp_to_next_level(level) = 60 + (level-1)×40`（Lv1→2 需 60，逐级递增），上限 `LEVEL_CAP = 6`，累计约 700 经验满级。
- 升级只增加 `unit_data.json` 配置的等级属性（力量/灵巧/智力/信仰/体力/移动）与等级机制（射程 +1 / 移速 +1 / 暴伤 +20% / 物穿 / 魔穿 +10%），不弹新选择、不 gate 转职或流派。
- 每局净增约 1~2 级，避免等级掩盖 build 差异；`start_new_cycle` 会同时重置 `level=1` 与 `experience=0`。
- 装备界面不再显示升级按钮（`_is_level_up_enabled()` 恒 false），也不再花金币升级；`unit_level_up_cost` 仅留历史配置，不作玩家可见消耗。
- GM 控制台 `levelup` 为调试入口，绕过经验/金币/上限。

**战场升级仪式感（v6.58）**：升级瞬间播 get_item 音效 → 0.25 秒真实时间停顿（不受倍速影响）→ 单位上方弹出白色 "LVn" 跳字（与伤害跳字同字号）。多个单位同时升级时，胜利界面会等所有升级表演（以及 Boss 死亡对话）结束后才弹出。

**等级显示**：所有展示单位信息的局内界面都显示「当前/最大等级 + 当前经验/升级所需经验」——战场悬停面板、单位信息面板（含选人/竞技场/派遣/魂祭坛的 fallback）、装备配置详情、防具/技能 roll 单位卡。满级显示 MAX。

**局外等级上限**：魂祭坛（SoulAltar）花魂提升的 `unit_level_cap` 是另一套局外系统，本轮保留，与局内等级成长相互独立。

### 5.8 战斗系统

伤害公式与核心常量沿用 v5：

```text
物理攻击 = 武器攻击×品质倍率 + 力量×系数 + buff
         × (1+buff_attack_percent)
         × (1+力量×relic_strength_scale_damage)

物理减伤 = clamp(单位基础+防具+词条+buff+地形+低血减伤, 0, 75%)

最终伤害 = max(攻击×10%, 攻击×(1-减伤+穿透))
```

暴击：

- 基础 5%；
- 每点灵巧 +0.5%；
- 暴击伤害倍率 1.5，上限 2.0；
- ~~枯竭时 +0.5 暴伤~~（v6.62z 删除，低魂火/归零无额外增益）；
- 余烬机制在魂火耗尽时提供下击必暴。

攻击流程：

```text
主动技能判定与前扣魂火
  → 基础伤害 + 技能倍率 + heavy 倍率
  → 流派机制触发（灼烧 / 反弹 / 回魂火 / 扣血换攻等）
  → 暴击判定 → parry/block → 应用伤害
  → 命中回魂火 on_hit(1)
  → 溅射 / AOE → 击杀检查 → 击杀钩子（含击杀经验，见 5.7）
  → Boss 形态拦截 → 吸血 / 连击 / 反击 → 清理临时状态
```

流派机制必须走统一出口，避免同名不同义。战斗层与持久层继续隔离：Build 临时增量胜利后同步，失败 / 中途退出回滚。

**击杀即判胜（v6.57）**：任何伤害来源让敌方单位 HP 从 >0 变 0 时（下沉到 `Unit.apply_damage`），立即排队一次胜利判定，不再依赖单一 `_on_kill` 路径。Boss 多形态在最终形态归零即当帧判胜并锁输入，杜绝"已死但能踩格子却拖到下一回合才胜利"的问题。

**敌方死亡掉落物**：敌方单位死亡有概率掉落血球，`item_battlefield_data.json` 配 `name` / `description`（含 `{v}` 占位符用 `heal_percent` 替换）。鼠标悬停掉落物时复用战场信息面板，显示 JSON 里的完整描述（如"血球 / 拾取后回复 25% 最大生命"），不再硬编码文案。

### 5.10 献祭赋能（v6.62：熔铸机制全面改造）

**旧机制（产出 `melt_` 专属防具）已废弃**。献祭不再是"牺牲一个换一件强力防具"，而是**把献祭单位的基础数值加到幸存单位上，让幸存单位超级化**。机制从魂栈节点移入**英灵殿（CHAPEL）**，与复活 / 转职同处一地。

**核心规则**（用户拍板方案）：

- **只加基础数值，经验 / 等级保持不变**：把献祭单位的 `max_hp / 力量 / 灵巧 / 智力 / 信仰 / 移动 / 攻击 / 物减 / 魔减 / 物穿 / 魔穿 / 固定暴伤` 共 12 项基础数值（**含升级后的当前值**）加到幸存单位。经验与等级**不相加、不重算**——避免数值二次膨胀与 Lv6 上限溢出。HP 上限增加时当前 HP 同步增加，不会"超级化却残血"。
- **装备 / 技能 / 流派冻结、不继承**：献祭单位的防具、技能、流派做完整快照存入幸存单位的 `empowerment_source`，随即从献祭单位身上清空并标记 `is_dead`。被献祭单位暂时不可用，其机制不转移给幸存单位。
- **已赋能单位的限制**：不能再次献祭、不能转职，但**可以正常升级**（升级照常走 5.7 的击杀经验）。取消赋能（见下）后恢复可转职。

**操作流程**：

1. 英灵殿中每张存活单位卡片**下方（拉开间距）**有「献祭」按钮；**已赋能单位 / 阵亡单位的按钮禁用**（第三个存活单位才可献祭）。英灵殿抬头「英灵殿」文字在画面中居中（TopBar 用左右对称 Spacer）。**不显示持有资源**（v6.62i）：本界面转职免费、献祭赋能不消费魂/魂火/金币，故直接从场景删除 TopBar 的持有魂数量（`GoldLabel`）与「转职：免费」（`CostLabel`）两个节点及对应脚本引用，TopBar 只留左右 Spacer + 居中标题。
2. 点击后复用 `ConfirmUI` 弹确认界面，**剩下两个存活单位左右并排**、各显示为**单位头像 avatar 按钮**（`UnitDataManager.create_unit_avatar_button`，非战场序列帧图；用 `show_choice(..., horizontal=true)` + 卡片 `avatar_unit` 字段），底部有「取消撤回」按钮。avatar 按钮与卡片均有鼠标悬停提亮反馈（v6.62b）。
3. 点任意一个 avatar = 赋能成功：`SacrificeHelper.empower_unit()` 执行数值相加与快照冻结 → 播单位升级音效（get_item）→ 回到英灵殿 → 单位卡片与详情立即刷新显示「★ 已超级化」及变化后的数值。
   - v6.62b 起单位卡片的"可转职 ★分支列表 / 点击查看"详情**不再显示**，只留简短「可转职」状态，避免信息过载。
4. 候选只剩 1 个存活单位时改用普通 `show_confirm` 单卡片确认。
5. 赋能结果通过 `UnitData.is_empowered` / `empowerment_source`（含 to_dict/from_dict）持久化，此后局内各界面（战场、装备、roll 卡）读同一单位数据，信息自动同步。
6. **赋能单位外观统一替换（v6.62p）**：所有显示赋能单位图片/动画的地方改用 `res://content/images/characters/unit_overlord_frames.tres`（含 idle/down/side/up 四动画，与战场动画名一致）：战场 `Unit._resolve_sprite_path()` 判 `is_empowered` 优先返回该资源（覆盖转职/override/Boss 变形）；竞技场 `ArenaBattle._setup_unit_sprite` 同步；装备界面头像 `create_unit_avatar_button(..., empowered)` 与英灵殿卡片 `create_idle_texture_rect(..., overlord_path)` 走同款。路径常量 `UnitDataManager.EMPOWERED_FRAMES_PATH`，头像 idle 首帧带缓存 `get_empowered_idle_texture()`。

**取消赋能 = 复活献祭单位**：被献祭单位一直躺在英灵殿；玩家点复活它时，`GameState.revive_unit()` 找到持有其快照的被赋能单位，调 `SacrificeHelper.restore_empowerment()`——从幸存单位**扣回**数值增量、清赋能标记、把冻结的装备 / 技能 / 流派 / 转职还原给复活的献祭单位。这是唯一的取消赋能入口（不另设独立按钮）。

**代价周期**：与旧熔铸一致，献祭只在当前 3 天 cycle 内有效；进入下一 cycle 时 `start_new_cycle` 复活所有单位并清空赋能，队员无偿归队。这是"局内战术取舍"而非永久损失。

<details><summary>旧熔铸口径（v6.61 及以前，已废止，留档）</summary>

牺牲一个单位，获得该职业专属 `melt_` 防具；防具不可改 / 卖 / 合成 / 覆盖，绑定亡者，复活可取回。`SacrificeHelper.do_sacrifice()` 与 `describe_melt_reward()` 保留为兼容接口（营地的旧熔铸入口 `ForgeAltar` 仍调用），但地图节点的献祭已全部走新的赋能流程。

</details>

## 七、试玩观察指标

### 目标区间

- 开局 roll 用时 <45 秒。
- 战后防具 roll + 领取用时 <60 秒。
- 魂栈停留 <60 秒。
- 燃烧态占比 40–60%。
- 燃烧态占比 40–60%。
- 归零 / 低魂火占比不作负面指标；观察玩家是否主动保留魂火维持燃烧，以及魂火爆发使用频率。
- 三天通关率 >30%。
- 主动技能消耗提示可见率 100%。
- 防具 roll 覆盖 / 放弃决策出现率 >30%。
- 遗物三选一跳过率 <20%。

### 人工观察

- 玩家是否能一句话说出自己单位的 build。
- 同单位不同开局技能是否真的产生不同玩法。
- 同流派并入升 Lv 是否有即时爽感。
- 满槽覆盖是否痛但不困惑。
- 1 槽单位是否显得过于单薄。
- 3 槽单位是否造成认知负担。
- 消耗型遗物是否产生“现在用还是留着”的判断。
- 玩家是否还会寻找“方向 / 连通 / 词条重洗”等旧操作。

### 主要风险

1. 六流派机制接线与竞技场对齐工作量大。
2. 防具 roll 价格沿用商店数据，节奏可能偏贵或偏便宜。
3. 开局技能仅 1 次重掷，运气方差仍需试玩确认是否足够。
4. 技能与流派共鸣已于 v6.72 删除——原担忧「common + 共鸣相当于 rare」掩盖品质差异的问题随之消失，流派 Lv 现在严格由防具品质/件数决定。
5. 3 槽单位前期可能过强或信息过载。
6. 删除连通 / 方向后，部分老玩家可能感到深度下降。
7. 竞技场暂不同步，短期会出现两套装备口径。

## 八、设计哲学

- **选择而非计算**：玩家定流派、定给谁、定覆盖谁；系统跑腿。
- **单件即机制**：第一件装备就改变打法，不靠凑数。
- **同流派并入**：后续装备升同一条机制，不制造背包。
- **槽位是引擎数**：单位 1/2/3 槽代表能同时开几个流派。
- **技能是随机起点**：roll 池受单位可装备限制，不写死流派身份。
- **转职是固定第二格**：不被 roll、不被覆盖，保持身份感。
- **遗物统一化**：取消独立光环系统，只保留持续型 / 消耗型两种生命周期。
- **成长自动化但来源清晰**：等级不再制造操作（击杀自动给经验、自动升级、带仪式感反馈），build 差异优先于等级差异；玩家能看到当前/所需经验，但不用手动操作。
- **删除冗余比新增更有价值**：方向、连通、背包管理、商店比价都退出玩家层；v6.59 连难以理解的站位阵型系统也一并移除，build 深度回归单单位流派选择。
- **装备重要性靠机制表达**：不是让玩家更忙，而是让每次选择更有后果。
- **主线与竞技场口径统一**：核心 build 机制与经验规则在主线和竞技场保持一致。
- **配置随资源走，不随槽位走**（v6.62）：胜利条件这类"归属地图"的配置放在地图场景 trigger 里，不挂在运行时随机的节点槽位上；玩家在选路时就能看到目标。
- **牺牲换持续战力，不换一次性道具**（v6.62）：献祭的价值留在队伍里（幸存单位超级化），且可撤销（复活献祭单位即完整还原），避免"永久损失"的心理门槛。

## 十一、整局可玩性评估（v6.62j，结合代码）

本章评估**整局游戏**的可玩性，覆盖战斗 / 经济 / 地图 / 成长 / 防具 / 闭环，而非单一系统。基于当前代码实现与实际数值，非纯设计推演。

**总体结论**：v6 完成了从"配装模拟器"到"选择组成 build"的转向，核心手感目标（选择而非计算、单件即机制）在代码层成立。经 v6.54 澄清后，转职无等级门槛、献祭 / 熔铸代价仅局内 3 天均为**有意设计**（文档已对齐），不再是问题。v6.62 又补上了两处结构性问题：胜利条件归属到地图场景（不再随随机节点错配）、魂栈改为遗物商店 + 老虎机遗物（给吃紧的金币经济多一条"先投资降本再收益"的路线）与献祭赋能（牺牲价值从一次性防具改为持续战力）。v6.62z 已针对性调整 **3 个体验断点**：首次 50G roll 与金币产出上调缓解金币紧张、封顶全额退款与「返还金币/注入词条」二选一消除浪费、魂火改两态（归零无增益无惩罚）重构张力；均不需要推翻架构。

### 11.1 核心循环与决策密度 — 成立

完整循环：`开局选 3 单位 → 3 次主动技能 roll 落位 → 地图 3 天 → 战斗 → 战后防具 roll → 领取台决策 → BOSS → cycle 结算 → 回营地`。全程无终局、无限循环（设计如此，非死局）。

与 v5 对比，玩家的日常操作被压缩到三类决策（开局技能、战后防具、遗物三选一），系统承担所有计算——这是 v6 最重要的达成。第七章的决策密度表（战斗内 ★★、地图查看 ★）与实际实现一致：战斗内玩家能移动/普攻/技能/急救/走位，但不能再摆方向、凑连通、管背包；v6.59 起站位阵型配合也已移除，走位不再隐藏触发额外机制。

**风险**：存在完整自动战斗流水线（`AllyAutoBattleManager`，默认关闭但一键托管）。它会捡血瓶、急救、按魂火阈值放技能、Boss 时爆发——对"魂火状态管理"这一核心微循环而言，一键托管等于把决策层整个跳过。若试玩发现多数玩家开自动，v6 的"选择"哲学在战斗层就是空转。

### 11.2 战斗系统 — 机制齐备，操作价值需验证

- 魂火设计为两态：燃烧增益 / 正常无增益。归零或低魂火不承担负面惩罚，也不提供额外增益；张力来自“消耗魂火换技能/爆发”与“保留魂火维持燃烧”的取舍，而不是“低魂火变强或变弱”。余烬流派的“魂火耗尽时下击必暴”是该 build 的主动选择，不是通用状态。目标区间相应改为只观察燃烧占比，不再要求枯竭占比。
- 六流派 hook **全部接线**（烈焰灼烧、轮回击杀回魂、灰烬地块、守护反弹、献祭换攻、余烬必暴），竞技场也同步。这解决了第七章风险 1 的大半。
- 伤害公式（减伤上限 75%、保底 10%、暴伤上限 2.0）与文档一致。
- 技能共鸣已于 v6.72 删除，原「common+共鸣是否掩盖品质差异」的担忧不再适用（见 7 章风险 4 的后续说明）。

### 11.3 经济与 roll 节奏 — 偏紧，是主要怀疑点

| 项 | 实际数值 |
|---|---|
| 战斗金币产出 | START/NORMAL 300、ELITE 500、BOSS 700（v6.62z 上调） |
| 一局总量 | 约 7–9 场战斗 ≈ **2600–3800 金**（v6.62z 上调后） |
| roll 成本 | 每场首次 50G，之后 `100 + 50×次数`（可被节俭之轮 -20% / 定额筹码不涨价修正） |
| 品质升级 | v6.72：150/350/650/1000/1400（跨场持久，第二天初中期到顶） |
| 魂栈遗物 | 购买 120–220、刷新 100、出售返还 price×返还率（基础 50%，交易遗物可提升至 70%+） |
| 其他消耗 | 单位升级 250–6000 已停用（v6.58 起经验自动升级）；献祭赋能不花钱（代价是失去一个单位） |

**结论（v6.62z 前的诊断，已针对性调整）**：一局总收入只够约 8 次 roll，且这是不买品质升级、不买魂栈遗物的前提。v6.62z 以每场首次 50G + 产出上调（总收入 2600–3800）+ 品质升级降价（150/400 起步）三管齐下，目标把人均 roll 提到 10–12 次，让"覆盖/放弃决策出现率 >30%"具备达成条件；实测需验证该目标是否实现。

**v6.62 的缓解与新张力**：老虎机遗物提供一条"先投资、后回本"的路线——节俭之轮（-20%）+ 定额筹码（不涨价）显著降低长期 roll 成本，返利硬币再回 20%，理论上能把roll 次数拉高一截；但买入这些遗物本身就是金币支出，且与团队遗物、品质升级争抢同一份预算。魂栈出售遗物（返还 50%）则是被动回血口。**试玩重点**：统计"买老虎机遗物 vs 直接多 roll"哪条更划算——若投资路线明显更强，roll 经济瓶颈即被结构性化解；若收益太慢，玩家仍会跳过商店，商店沦为摆设。另需关注献祭赋能是否带来新的数值膨胀（两个单位基础值相加可能让幸存单位过强，压过 build 差异）。

### 11.4 地图与成长 — 结构清晰，口径已对齐

- **地图结构**：3 天/cycle，Day1 五节点、Day2 五节点、Day3 单 BOSS（起点图 map_start 已清理，不再混入普通池）。过天每单位 +1 槽（上限4）——已与前几轮修复对齐。
- **胜利条件归属（v6.62）**：胜利条件改为每张战场地图 trigger 配置，彻底解耦随机节点类型——之前"节点槽位随机成不同类型导致目标错配 / 丢失"的结构性问题消失。地图节点通过预读 scene 显示目标标记，玩家在选路时就能看到"占 / 旗 / 突"。默认全灭，13 张地图暂未配特殊目标，因此这一改动当前主要是**消除了隐患**，特殊胜利玩法的实际体验仍需配样板地图验证。
- **转职（v6.54 确认为有意设计）**：无等级门槛，Boss 战后进英灵殿免费转职。等级不 gate 构筑身份。**v6.62 起**：被赋能单位不能转职，取消赋能（复活献祭单位）后恢复——这为"转职 vs 超级化"增加了一次取舍。
- **献祭赋能（v6.62）**：牺牲的价值从"一件专属防具"变成"幸存单位的基础数值翻倍级增长"。**收益直观（卡片数值立即变化 + 升级音效 + 全局同步）、撤销路径清晰（复活献祭单位即完整还原）**，比旧熔铸的"防具绑定亡者"更好理解。**平衡风险高**：两个单位基础值相加（含升级后值）可能造成幸存单位过强，压过 build 与流派差异；且赋能单位不能转职，可能让"三单位阵容"实际退化为"两个半"。经验/等级不相加是防二次膨胀的正确选择，但需实测超级化单位的战力是否溢出。
- **成长（v6.61）**：经验唯一来源是击杀（按敌方强度），战后不再发经验，阵亡单位当战不获得。击杀多的单位等级略高，但每局净增约 1–2 级、上限 6，等级不构成主要策略维度，符合"build 差异优先于等级差异"。

- **代价周期**：献祭 / 熔铸都只当前 3 天 cycle 有效，`start_new_cycle` 复活所有单位并清空赋能，无偿归队——这是"局内战术取舍"而非永久损失。第七章把它列为 ★★★★ 高密度决策的前提是玩家理解代价仅局内——若误以为永久，决策重量会被高估。
- ~~**遗物稀有度未实现**~~（v6.62r 已解决）：遗物数据新增 `rarity` 字段（common/rare/epic 三档，权重 10/4/1），22 件遗物全部分级；魂栈商店与战后三选一均改为按权重不放回抽取，稀有遗物掉率显著降低，编辑器提供中文下拉配置。剩余待实测：实际掉落体验是否匹配第七章"遗物三选一跳过率 <20%"目标。

## 十一·补、可玩性改进方案总结与落地（v6.70，2026-11-25）

> 原方案标题为「v6.68 可玩性改进方案总结（已移除方案 D）」。本节保留诊断/方案/优先级原文口径，并附 v6.70 落地结果。

### 两个核心问题的诊断

| 问题 | 诊断 |
|---|---|
| **组合乘数不足** | 当前协同是"加法式"的：3 个单位各养 1 个主流派，流派之间主要是数值并置；遗物也以全局数值修饰为主。两个选择放一起≈各自效果相加，而非相乘。 |
| **随机性修复出口偏少** | 出口集中在"结果落地后"（封顶退款/注入），缺少"抽不到想要的流派"时的可支付修正手段；开局技能仅 1 次重掷，防具 roll 无重掷。 |

### 剩余方案一览

**针对组合乘数不足：**

| 方案 | 内容 | 成本 | 状态 |
|---|---|---|---|
| A. 钩子型遗物 | 新增 2–3 件监听六流派已有钩子的遗物（"轮回击杀回魂火时给目标上灼烧""守护反弹时给攻击者上冻寒"），不新增按钮、只挂已有触发点，形成乘数耦合。 | 低，复用现有战斗接线点 | **v6.70 已落地** |
| B. 启用专精防具 | 启用 2–3 件 `affix_schools` 专精防具（烈焰/守护），把"随机撞组合"变成"定向凑组合"。字段已就绪，只需填配置。 | 低 | **v6.70 已落地** |
| C. 跨流派条件词条（暂缓） | 1–2 条双 tag 条件词条（如"余烬引信"），作为稀有惊喜。理解成本可能偏高，等 A/B 验证后再定。 | 中 | 暂缓 |

**针对随机性修复出口偏少：**

| 方案 | 内容 | 成本 | 状态 |
|---|---|---|---|
| E. 软保底 | 不做显性硬保底，在 roll 池内部做隐藏概率修正：防具连续 2–3 次未出新流派则提高未出现流派权重；开局技能最后一次 roll 优先保证至少一个能衔接已有消费链的技能。窗口放在第一天到第二天之间。 | 低，纯概率层 | **v6.70 已落地** |
| F. 一次性定向消耗品 | 低频消耗品"流派罗盘碎片"：下一次防具 roll 候选池强制包含指定流派一件，每局最多 1–2 个，150–200G。 | 中 | P2 未落地 |

### 建议优先级

| 优先级 | 方案 | 理由 |
|---|---|---|
| P0 | A（钩子型遗物 2–3 件） | 实现成本最低，直接回应乘数问题，且复用已有六流派钩子 |
| P0 | E（软保底） | 纯概率调整，不改 UI 和规则表述，与 A 并行落地 |

| P2 | F（一次性定向消耗品） | 高成本低频紧急出口，不影响基础经济 |
| 暂缓 | C（跨流派条件词条） | 等 P0/P1 验证后视理解成本再决定 |

#### ★ v6.72c 关键修复：soulfire_identity.json 死配置 → 真正加载

**根因**：`soulfire_identity.json` 从未加入 `GameConfigManager.FILES`，全库无直读 / reload 调用。`get_value()` 恒返回 null → 魂火身份表、燃烧/爆发身份、击退、位置后果配置全部走空兜底。后果分两层：
- **配置层**：改 JSON 任何数值都不生效（纯死配置）；
- **行为层**：`get_burst_trait()` 空兜底只返回 `{id:none}`，`cfg.get("knockback", 0)` 恒为 0 → **v6.67"已落地"的爆发击退运行时一次都不触发**；夹击/ZOC/危险地形则因硬编码兜底值恰好等于 JSON 值而"碰巧正常"。

**修复**：
1. `GameConfigManager.FILES` 加入 `soulfire_identity.json`。
2. `SoulFireIdentity._ensure_loaded()` 改为「读空不锁定」：首次访问若早于 `load_all()`，不再把 `_loaded` 永久置 true（此前死配置的第二重保险失效点）。

**加载后行为突变（预期，待实机验证）**：整张身份表一次性激活——爆发阈值从统一 3 变为按单位 3/4/5（剑士/弓手/枪兵/斧手 4，重甲/牧师 5，法师/飞马/龙裔 3）；剑士 1 格 / 枪兵 2 格击退真正触发；横扫/法师 AOE+灼烧/牧师群疗+回魂/重甲嘲讽护盾/穿甲/眩晕/龙息等 `burst_trait` 字段全部生效。位置后果（撞墙/连撞/危险地形/ZOC/夹击）从"碰巧用硬编码"变为"读配置生效"。

**同步清理的确认死项**：`economy_config.json` 删 `soul_altar.weapon_forge_cost` / `selected_layout` / `params.runs` / `params.soul_per_run`（全库零读取）；`soulfire_identity.json` 删 `position.danger_terrain.hint`（`danger_hint()` 无调用者）；`unit_data.json` 删孤儿 `boss_dragonlord_form2`（phases 实际用 form3）；`TurnController.gd` 删 4 个无人调用的旧副本函数（`_apply_turn_start_auras` / `_apply_turn_start_aura_effect` / `_apply_turn_start_fusion` / `_apply_charge_stacks`，真正实现在 `TurnManager.gd` 且有调用）。**保留未删**：`soul_drain` boss 机制（有真实处理分支，属预留可达）、aura 遗物 effects 镜像（删了会让编辑器面板显示"无效果"误导）、只写不读字段与单边信号（公共 API / 存档兼容，删有回归风险）。

### 「做了但没起作用」全库审计（v6.72g，2026-11-26，只读检查）

三个维度并行扫描（配置层 / 函数·信号·类 / 数据字段）+ 人工复核。分级口径：**P0 = 玩家可感知的功能缺口**，P1 = 数据冗余或预留但当前不生效，P2 = 死代码/预留 API（按减负方向可清）。

#### P0：身份表字段配了但战斗层不读（玩家可感知）

v6.72c 修复 `soulfire_identity.json` 加载后，文件活了，但其中大量 `burn_trait`/`burst_trait` 字段**战斗层没有消费分支**——配置改动仍不生效。复核确认零 `.get()`（同名的 `counter_boost`/`range_bonus`/`defense_shred` 命中均属天赋或技能 effect_params，与身份表无关）：

| 字段 | 所属身份 | 设计意图 | 现状 |

| `reflect` / `counter_boost` | 重甲燃烧 · 盾卫爆发 | 反弹 30% / 反击强化 | 无消费（反弹走遗物字段，非身份） |
| `pierce_targets` | 弓手燃烧 | 普攻穿透 1 目标 | 无消费 |
| `ignore_reduction` / `armor_break` | 弓手爆发 | 无视 50% 减伤 / 破甲 | 无消费 |
| `second_target_multiplier` | 枪兵燃烧 | 直线贯穿第二目标 50% | 无消费 |
| `pass_through` | 飞马燃烧 | 穿越敌方单位 | 无消费 |
| `stun_rounds` | 飞马爆发 | 俯冲眩晕 1 回合 | 无消费 |
| `reset_action_on_kill` / `per_battle_once` | 斧手爆发 | 击杀再行动 / 每场 1 次 | 无消费 |
| `breath_multiplier` | 龙裔燃烧 | 锥形龙息 +30% | 无消费 |
| `leave_ash_tile` | 龙裔爆发 | 留燃烧地块 | 无消费 |

**对比已生效字段**（有 `.get()` 分支）：`damage_bonus`、`damage_reduction`、`heal_bonus`、`soulfire_on_heal`、`adjacent_multiplier`、`aoe_multiplier`、`burn_stacks`、`team_heal_ratio`、`soulfire_gain`、`taunt_rounds`、`shield_damage_reduction`、`knockback`、`move_bonus_override`、`zoc`、`burst_threshold` 等。也就是说 v6.64 设计的 9 单位身份**只有约一半真正落地**。

### 死机制审计修复落地（v6.72i）

对上节 v6.72h 审计的 P0/P1/P2 逐项修复（保留项见文末说明）：

**P0 身份表字段消费补齐（18 个）**——`soulfire_identity.json` 加载后真正生效的字段从约 15 个扩到 33 个：
- 爆发附加（`CombatManager._apply_burst_trait_effects`）：`cleanse`（全队清异常/禁疗/减速）、`stun_rounds`（目标眩晕）、`armor_break`（目标破甲 30%）、`detonate_burn`（消费目标灼烧层 ×0.25/层追加伤害）、`leave_ash_tile`（目标格留燃烧地块）、`hit_count`/`hit_multiplier`（狂战士多段突进）、`reset_action_on_kill`/`per_battle_once`（斧手击杀再动，在 `_on_kill` 消费并置 meta 防重复）；`ignore_reduction`（弓手爆发按配置比例无视减伤重算主伤害）。
- 燃烧被动：`reflect`（重甲燃烧态受击独立反弹）、`pierce_targets`/`second_target_multiplier`（弓手/枪兵沿主轴贯穿第二目标，新 `_apply_burning_pierce`）、`pass_through`（飞马燃烧态寻路可穿过敌方格但不停靠，`UnitManager._unit_can_pass_through`）、`breath_multiplier`（龙裔锥形龙息）、`move_after_attack`（狂战士燃烧态攻击后再移动 1 格，`Unit.can_move` + meta 防重复）；`tint`（转职外观色调，`Color.is_valid_html_color` 解析后应用 sprite modulate）。

**P1 冗余配置清理**：`talents.json` 删 `scaling` + `unit_type_scaling` 各 17 处；`relic_data.json` 删 6 件 aura 遗物的 effects 冗余镜像（真实效果仍读 `auras.json`）；`set_bonuses.json` 删 6+4 个 `name`、`move`/`defense` 死字段（保留 effect/value 兜底与 description 供 UI）；`special_items.json` 删无消费的 `max_stack`；`economy_config` 删 `forge.max_slots`、`combat_config` 删 `rare_drop_chance.START`、`item_battlefield_data` 删 `despawn_turns`；删除从未加载的 `treasure_rewards.json` 及 `Config.PATHS` 条目；删 `Unit` 三个纯死字段（`moves_since_act`/`active_skill_ready_consumed`/`used_non_attack_item_this_turn`）及赋值点。

**P2 死代码与信号**：`GameConfigManager._after_reload` 接入 `SoulFireIdentity.reload()` 与 `EnemyIntentManager.reload_config()`（修配置热重载缺口）；删除 `Battlefield` 里重复的血球 HUD 死实现（信号未 emit 导致永不显示，真实血球走 `ItemBattlefieldManager` 自带 sprite 实体）与 SignalBus 两个血球信号；删零引用信号 `unit_moved`/`request_highlight`；删死函数 `SoulFireIdentity.get_hud_icon`、`BuildManager.is_safe_placement`、`TurnManager._apply_turn_start_auras`/`_apply_turn_start_aura_effect`；编辑器白名单删 `three_forms`/`kill_heal`/`dodge`。

**保留未删（有回归风险）**：`treasure_rewards` 删除但保留 economy_config.treasure 真实路径；`events.json` 11 事件数据/触发代码完整但地图无 EventTrigger 节点配置——需设计决定挂点，保留并在审计节标注；`overwrite_school`（完整实现但当前无调用）、`GridPushManager.get_cells_for_threshold`（击退查询 API）、`DialogueManager.start_dialogue`（废弃桩有重定向）、`move_and_defense` 白名单（set_bonuses 旧 effect 兜底仍用）、其余约 190 个 autoload/private/public 预留 API 与 6 个单边信号——按减负方向可后续分批清理，本轮不动以避免回归。

**校验**：23 个 JSON 全合法、14 个改动脚本括号配平全 0、静态调用一致性无 static 误用、15 项 P0 字段接入断言全 PASS。环境无 Godot CLI，需编辑器实机验证 P0 新机制节奏（尤其多段/贯穿/再动是否过强、飞马穿越寻路是否正常）。
