## 一、版本定位

v5 把《魂火》做成“状态管理 + 标签配装”的肉鸽：魂火负责短循环，6 标签贯穿系统，FORGE 是决策爆发点。实际游玩后暴露的问题是：**装备系统操作强度过高**。玩家大量时间花在比较词条、摆方向、凑连通、管理背包和覆盖装备上，而不是表达 build。

v6 的核心转向：

> **玩家通过选择组成 build，而不是花时间配装。装备的重要性来自“第一件即觉醒机制”，不是来自操作复杂度。**

v6 把玩家日常操作压缩为三类：

1. 开局主动技能 roll → 点单位落位；
2. 战后防具 roll → 点单位落位 / 覆盖 / 放弃；
3. BOSS 后或宝箱遗物三选一。

系统承担所有计算：槽位、方向、连通、词条数值、品质上限、套装判定、成本结算。

### v6 相对 v5 的核心变更

1. 地图装备界面**保留 EquipmentConfig**（v6.4 回退只读方案）：装备与遗物可拖拽调整位置，但开局 roll 的技能词条锁定，特技库入口禁用。
2. 商店不再是一个地图节点功能；防具获取改为**战后金币 roll**。
3. 开局选 3 单位后，从这些单位可装备的主动技能中 roll 3 次，形成随机起点。
4. 每单位技能词条上限 2 格：第 1 格开局 roll，第 2 格转职获得；两格锁定。
5. 防具从数值套装改为**单件觉醒机制 + 同流派并入升 Lv**。
6. `armor_slots` 语义改为**机制槽**：一个流派占一格，同流派后续防具不占新槽。
7. 魂栈去掉商店 / 铁匠 / 光环，只保留**熔铸单位**这一单一功能。
8. 光环并入遗物：多数为持续型，少数产魂火光环为消耗型遗物。
9. 连通、箭头、装备界面单位交换位置从玩家层移除。
10. 单位升级改为**击杀敌人即时获得经验**（按敌人强度配置，唯一来源），自动升级；装备界面不再有升级按钮。详见 5.7。
11. 战后结算不再送防具；宝箱不再提供防具选项。
12. 竞技场已同步主线核心机制（见 5.11）。

### 保留的 v5 骨架

魂火三态、命中回魂火、魂火跨节点继承、六流派标签、四层循环、七组张力、熔铸单位、遗物三选一、局外魂成长、派遣、剧情、竞技场、编辑器生态、伤害公式、减伤率 75% 上限、最低保底 10%。

## 二、核心体验

v6 的体验重点从“我把装备摆对了吗”转为：

- 这局我的三个单位分别拿到什么主动技能？
- 这件防具要开新流派，还是喂给已有流派升 Lv？
- 这个流派是该给主核，还是给副核开第二机制？
- 满槽时，我愿意放弃哪一个机制？
- 遗物三选一，是补队伍短板，还是强化主流派？

玩家不再做算术题。每个选择都有一句话后果预览：

```text
给剑士 → 觉醒烈焰（攻击附带灼烧）
给守卫 → 并入烈焰 Lv2
给法师 → 新增守护反弹（主流派仍烈焰）
```

装备仍是 build 核心，但它的价值表达从“+10% 攻击”变成“这单位从此会灼烧 / 反弹 / 击杀回魂火”。

## 三、核心循环

### 3.1 开局循环

```text
选择 3 个单位
  → 生成主动技能轮盘池
  → 转 3 次（玩家点开始 / 停止选技能）
  → 点单位落位
  → 进入地图
```

- roll 池 = 已选 3 单位 `compatible_units` 的并集。
- 3 次 roll 不重复同一技能 ID。
- 不提供重掷。
- 不兼容单位灰显并说明原因。
- 点击单位即锁定，不能互换、不能撤销。
- 转职后获得第 2 格技能词条，固定内容、灰显不可操作。
- **转职触发（v6.54 确认）**：无等级门槛。Boss 战后进入英灵殿（CHAPEL）即可转职，免费；不为转职设"5 级"等等级条件——等级只影响属性，不 gate 构筑身份。

主动技能覆盖：

| 单位 | 可 roll 的主动技能 |
|---|---|
| archer | 狙击 |
| cleric | 群体治愈 |
| mage | 火球 |
| swordsman | 冲锋 |
| spearman | 冲锋、贯穿 |
| pegasus | 俯冲、狙击 |
| armored | 蓄力斩、嘲讽 |
| axeman | 蓄力斩、嘲讽 |
| dragonborn | 贯穿、火球、龙息 |

任意 3 单位并集最小为 3 个技能，刚好支持 3 次不重复 roll。

### 3.2 战斗循环

微循环仍是魂火状态管理：

```text
接敌 → 命中 +1 魂火 → 燃烧 / 枯竭 / 正常切换 → 技能与普攻取舍
```

击杀敌人即时获得经验（按敌人强度，唯一来源），满足阈值即自动升级（带 0.25s 停顿 + 白色 LV 跳字 + 音效的仪式感）。玩家不再在装备界面花金币手动升级单位。详见 5.7。

### 3.3 战后循环

```text
战斗胜利（击杀即判胜，信号在 HP 归零帧末发出）
  → 等待全部表演收尾 + 缓冲（v6.60，见 5.8）
  → 结算金币 / 魂 / 解锁
  → 防具轮盘（金币，玩家停轮选结果，每次 +50G）
  → 停轮后停留 0.5s 展示抽到的防具（期间不可操作）
  → 落袋界面：装备 / 并入 / 转向 / 放弃
  → 继续地图
```

战后结算不再出现防具卡片，不再有稀有防具掉落。胜利界面（v6.60）会先等 2 帧让击杀触发的攻击链启动，再等到**所有表演标志清空**——整条攻击链 `is_performing_action`（覆盖 Boss 死亡对话、死亡动画 0.58s）、获得物品弹窗、升级跳字计数、淡入淡出——最后再留 **0.4 秒真实时间缓冲**（不受倍速），节奏不急促；战后经验升级的跳字在弹面板前会再等一次。8 秒超时兜底防止标志残留卡死。这样避免"已判胜但面板在表演前就弹出/节奏太快"。防具轮盘停轮后固定停留 0.5 秒真实时间（不受倍速影响）展示结果，让玩家看清抽到了什么。

### 3.4 节点循环

```text
START / NORMAL / ELITE / BOSS
  → 魂栈：熔铸单位（无商店、无铁匠、无光环）
  → 宝箱：遗物 / 金币 / 魂，无防具
  → BOSS 后：遗物三选一
  → 英灵殿：复活 / 转职
```

## 四、玩家决策密度

| 阶段 | 密度 | 决策 |
|---|---|---|
| 开局选 3 单位 | ★★★ | 阵容与起点 |
| 开局主动 roll | ★★★★ | 技能给谁，固定随机起点 |
| 战斗内 | ★★ | 普攻 / 技能 / 魂火爆发 / 走位 |
| 战后防具 roll | ★★★★ | 流派落点、覆盖取舍、金币投入 |
| 魂栈熔铸单位 | ★★★★ | 失去单位换机制防具 |
| BOSS / 宝箱遗物 | ★★★ | 持续型 / 消耗型遗物取舍 |
| 转职 | ★★★★ | 获得第 2 技能词条与被动 |
| 地图装备查看 | ★ | 只读理解 build |

FORGE 不再是“商店 + 铁匠铺 + 合成 + 熔铸 + 光环 + 刷新”的高压节点，而是低频战略节点。

## 五、核心系统详解

### 5.1 魂火系统

魂火仍是一个数值、三重身份：

| 身份 | 表现 |
|---|---|
| 资源 | 主动技能、魂火爆发、破盾等消耗 |
| 状态 | 燃烧 / 正常 / 枯竭，归零并入正常并 HUD 标记“熄” |
| 续航 | 战后 100% 写回持久层，跨节点继承 |

三态：

| 状态 | 触发 | 效果 |
|---|---|---|
| 燃烧 | > 50% 上限 | 移动 +1，攻击溅射 50% |
| 正常 | 20%–50%，或归零 | 无 |
| 枯竭 | 0 < 魂火 < 20% | 暴击伤害 +50% |

获得口径：

- 命中 +1，包含普攻、追击、溅射、AOE、反击等命中结算。
- 我方单位阵亡 +5。
- 归零态击杀 +1 作为触底反弹补偿。
- 装备 / 遗物 / 流派机制的击杀回魂火钩子按新机制结算。
- 战斗奖励发放“魂”，不发放魂火。

主动技能消耗必须在释放瞬间前扣，并显示“消耗 N 魂火”；命中 / 击杀收益在之后结算，避免净变化看起来为零。

魂火爆发：≥3 魂火时可消耗全部，强制暴击并附加额外伤害，使用后强制结束行动。

### 5.2 流派与标签

6 个流派：烈焰 / 轮回 / 灰烬 / 守护 / 献祭 / 余烬。单位不再预设流派，流派身份每局由玩家选择形成。

| 流派 | 机制 | 战斗接线点 | Lv1 / Lv2 / Lv3 / Lv4 |
|---|---|---|---|
| 烈焰 | 攻击附带灼烧，可叠层 | `CombatManager._apply_damage_with_effects` | 本次伤害 15% / 25% / 35% / 45% 追加无视减伤伤害 |
| 守护 | 受击反弹伤害；格挡触发时翻倍 | `CombatManager._apply_damage_with_effects` | 反弹 30% / 45% / 60% / 75%，格挡当次 ×2 |
| 轮回 | 击杀回魂火（与命中 +1 分开结算） | `CombatManager._on_kill` | 额外 +2 / +3 / +4 / +5 魂火；Lv2 起击杀额外治疗最低血队友 8% HP |
| 献祭 | 每回合扣血换本回合攻击 | `TurnManager._apply_school_turn_start` | 扣 3% / 4% / 5% / 6% HP（保底 1 HP），攻击 +10% / 15% / 20% / 25% |
| 灰烬 | 移动后从起点留下燃烧地块 | `Battlefield` 移动完成 → `CombatManager.drop/trigger_ash_tile` | 踩中受 3 / 5 / 7 / 9 伤害，活到下一次我方回合，场上最多 12 块 |
| 余烬 | 魂火耗尽时下一次攻击必暴 | `CombatManager.execute_attack` 暴击链 | 必暴并追加暴伤 +10% / +20% / +30% / +40%，魂火恢复后重新装填 |

具体数值可调，但原则是：**一件即完整生效、一句话能说清、穿上就改变打法**。所有机制都读 `BuildManager.get_effective_school_level(unit, school)`，不再各自解析防具。

**Build 配合的方向：单位之间，而非单单位多流派。** Build 的深度来自"队伍里谁穿什么流派、彼此怎么互补"——例如守护单位在前排反弹、轮回单位在后方击杀回魂火、灰烬单位封走位制造地形。一个单位原则上只追求**一个主流派升到高 Lv**（机制槽允许临时挂第二流派，但那是应急而非构筑目标）。因此**不设"同单位双流派组合技"**：v6.34 曾实验的 `BuildManager.SYNERGIES`（野火/血祭/背水/收割/焚身五个单单位双流派联动）已于 v6.36 移除——它与上述方向相反，且只有数据层与竞技场简化数值、主线战场从未接线，属于半成品。

**单位间配合已移除（v6.59）**：v6.37 曾在 `FormationManager` 实现六组站位阵型配合（F1 燎原 / F2 铁壁护卫 / F3 轮回链 / F4 血祭传递 / F5 余烬引爆 / F6 灰烬火墙），靠格子相邻触发。因理解成本过高，v6.59 已整套移除——包括效果触发、彩色连线、详情面板「阵型:」行与相关信号；`FormationManager` 从 autoload 移除并置为空壳。现在的 build 深度**只来自单单位流派选择**（上表六流派各自的机制），不再有"谁站谁旁边"的隐藏规则。`docs/TeamSynergyDesign.md` 已作废，仅留档。

### 5.3 主动技能词条

技能上限：每单位 2 格。

| 格位 | 来源 | 规则 |
|---|---|---|
| 第 1 格 | 开局 roll | 从单位可装备技能中 roll，点单位锁定 |
| 第 2 格 | 转职 | 转职分支固定获得，灰显不可操作 |

规则：

- 两格技能词条都不可互换、不可重洗、不可覆盖。
- 选定离手；装备界面只展示，不操作。
- 主动技能释放时显示魂火消耗与冷却。
- **通用轮盘老虎机（v6.3）**：开局技能与战后防具 roll 都改成「玩家点开始 → 看准图标点停」的转轮，带加速/减速过程；结果与停止时机绑定，**玩家选而不是系统直接给**。轮盘组件 `SlotMachineUI.gd` 可复用，**纵向只显示上一条 / 当前 / 下一条三行（图标 + 技能名），当前行金色高亮；右侧同一个按钮空闲时是开始、旋转时是停止，停轮后禁用、不再提供「再来一次」**；转轮用真实时间推进，不受游戏倍速影响，且节奏放慢（启动 0.16s  gradually→0.085s，停止后 8 格减速）。技能轮盘池为已选 3 单位 `compatible_units` 并集（已扩充为 17 个主动技能，且单技能兼容 3~5 个单位；群体治愈因治疗机制限制仍仅 cleric），并按「剩余单位是否仍能安全落位」动态过滤，确保停到的技能一定有人可装；防具轮盘池为当前品质权重下抽出的 8 件候选防具。**停轮后停留 0.5 秒真实时间展示抽到的防具（v6.58）**，期间全程锁定不可操作，之后才进入落袋界面——解决"还没看清抽到什么就被切走"的问题。
- 主动技能 × 流派共鸣（v6.2 冻结数值）：若单位身上的主动技能与某流派同标签，该流派机制按「有效 Lv = 防具 Lv + 1」结算，上限 Lv4。
  - 不新造第二套数值曲线：共鸣只借用上表已有的 Lv1~Lv4，玩家看到的仍是「Lv 变高、效果变强」。
  - 不叠层：同流派有两个技能也只 +1；不占额外机制槽；不写存档；单位没有该流派防具时，技能不会凭空开出机制。
  - 标签写在 `talents.json` 的 `resonance_school`（力量/敏捷等旧 `school` 字段是属性分类，与六流派无关）。九个主动技能已配：火球→烈焰、俯冲/龙息→灰烬、嘲讽→守护、冲锋/蓄力斩→献祭、群体治愈→轮回、狙击/贯穿→余烬。
  - 接线：`BuildManager.get_effective_school_level()` 是战斗层唯一有效 Lv 出口；`BuildViewer` 显示「共鸣 +1」，`SkillRollUI` 在 roll 卡上直接告知共鸣流派。
  - 与旧「每日火焰共鸣」区分：`LevelManager.current_resonance` 是按天全队 roll 的战场祝福（攻击 +5%、魂火上限 +1 等），与装备 build 无关；两者互不叠加、互不覆盖。后续建议把旧系统改名为「每日祝福」以防文案混淆。

### 5.4 防具与机制槽（v6.53 重构：词条即流派）

防具的角色被明确拆成两层：**防具承担基础数值，词条承担流派**。

```text
流派身份 = 该防具词条 tags 中的流派（按 SCHOOL_ORDER 取优先级）
已用机制槽数 = 单位当前觉醒的不同流派数
某流派 Lv   = 该流派累积的同流派防具贡献（受品质 cap 限制）
```

**核心变更（v6.53）**：流派不再由 `ItemData.tags` 判定，改由词条 tags 判定（`BuildManager.get_school_of_affixes`）。转轮 roll 时就生成词条（`roll_armor` 的 `entry.affixes`）并一路带到落位实例——修复了旧链路"落位防具词条为空"的问题。16 个词条全部带流派 tag（原唯一通用的"锋锐"归入烈焰）。

**落位三动作**（统一在 ConfirmUI 双选项面板 `show_choice` 中决策，见 5.5）：

| 动作 | 规则 | 玩家收益 |
|---|---|---|
| 强化（并入） | 同流派机制 Lv+1；**不 append 实例、不改已有词条** | 流派变强，已配好的词条与搭配完全不变 |
| 觉醒 | 空格遇到新流派 → 直接觉醒 Lv1，不弹面板 | 纯增益无取舍，不打断节奏 |
| 转向（置换） | 替换玩家点击的那个防具槽的流派，**100% 继承**旧流派 Lv/cap/count，新防具词条落到该槽 | 换 build 方向不归零，等级词条都带走 |

旧版"覆盖"（删光旧流派、新流派从 Lv1 重来、词条全清）已废弃；`overwrite_at_slot` 实现转向。机制上限仍为 common 2 / rare 3 / epic 4 / legendary 4。

**专精防具（v6.54）**：`ItemData.affix_schools` 可选字段——空=词条流派跟随防具 tags；非空=只允许该池流派的词条（`AffixManager.roll_affixes` 第三参数）。判定用方案 A：多 tag 词条（如灰烬护体带灰烬+守护）优先按防具锁定池归属，避免方向冲突。编辑器（`JSONEditorPanel`）用六流派下拉 + 增删按钮编辑此字段。**当前 50 件防具该字段均为空，功能已就绪但未启用数据。**

其余规则沿用：不同流派开新槽（受单位 1/2/3 槽限制，过天 +1 上限 4）；词条出生即定、只读、不可互换（16 条，品质挂 1/2/2/3 条）；方向/连通组/单位换位已从玩家层移除。展示口径见 `docs/ArmorSimplificationDiscussion.md`。

单位机制槽名单：

| 槽数 | 单位 | 理由 |
|---|---|---|
| 1 槽 | armored、dragonborn | 本体强，单机制专精 |
| 2 槽 | spearman、pegasus、archer、axeman、cleric | 大部分单位，主流派 + 副流派 |
| 3 槽 | swordsman、mage | 多分支成长，靠多机制差异化 |

### 5.7 单位成长（v6.58 重做）

等级系统保留，成长原则：**自动为主，来源清晰，不制造额外操作**。

**经验来源**：

- **击杀得经验（唯一来源）**：我方单位击杀敌人时，按被击杀敌人的强度获得经验。每个敌方单位在 `unit_data.json` 配 `exp` 字段（普通兵 25~60，Boss 80~200），代码读到 `UnitData.kill_exp`（`exp` 是 GDScript 内置函数不能作变量名）。所有击杀路径（普攻 / 溅射 / 反击 / 追击 / 灰烬地块）都经 `CombatManager._on_kill` 统一结算，溅射等间接击杀也计入击杀者。竞技场同理（`ArenaBattle._arena_on_kill`）。
- **胜利后不再发经验（v6.61）**：旧的 `VictoryHandler` 按节点类型 + 评级发额外经验、`Arena.gd` 战后发经验均已移除，评级只影响金币/魂等战利品，不再折算经验。经验唯一来源就是击杀。
- 旧口径"击杀/伤害/治疗/存活都进经验条"从未在代码实现，v6.58 起以击杀为准，v6.61 移除战后额外后更加纯粹。

**升级规则**：

- 经验满足阈值即自动升级，`BuildManager.exp_to_next_level(level) = 60 + (level-1)×40`（Lv1→2 需 60，逐级递增），上限 `LEVEL_CAP = 6`，累计约 700 经验满级。
- 升级只增加 `unit_data.json` 配置的等级属性（力量/灵巧/智力/信仰/体力/移动）与等级机制（射程 +1 / 移速 +1 / 暴伤 +20% / 物穿 / 魔穿 +10%），不弹新选择、不 gate 转职或流派。
- 每局净增约 1~2 级，避免等级掩盖 build 差异；`start_new_cycle` 会同时重置 `level=1` 与 `experience=0`。
- 装备界面不再显示升级按钮（`_is_level_up_enabled()` 恒 false），也不再花金币升级；`unit_level_up_cost` 仅留历史配置，不作玩家可见消耗。
- GM 控制台 `levelup` 为调试入口，绕过经验/金币/上限。

**战场升级仪式感（v6.58）**：升级瞬间播 get_item 音效 → 0.25 秒真实时间停顿（不受倍速影响）→ 单位上方弹出白色 "LVn" 跳字（与伤害跳字同字号）。多个单位同时升级时，胜利界面会等所有升级表演（以及 Boss 死亡对话）结束后才弹出。

**等级显示**：所有展示单位信息的局内界面都显示「当前/最大等级 + 当前经验/升级所需经验」——战场悬停面板、单位信息面板（含选人/竞技场/派遣/魂祭坛的 fallback）、装备配置详情、防具/技能 roll 单位卡。满级显示 MAX。

**局外等级上限**：魂祭坛（SoulAltar）花魂提升的 `unit_level_cap` 是另一套局外系统，本轮保留，与局内等级成长相互独立。

### 5.8 战斗系统

伤害公式与核心常量沿用 v5：

```text
物理攻击 = 武器攻击×品质倍率 + 力量×系数 + buff
         × (1+buff_attack_percent)
         × (1+力量×relic_strength_scale_damage)

物理减伤 = clamp(单位基础+防具+词条+buff+地形+低血减伤, 0, 75%)

最终伤害 = max(攻击×10%, 攻击×(1-减伤+穿透))
```

暴击：

- 基础 5%；
- 每点灵巧 +0.5%；
- 暴击伤害倍率 1.5，上限 2.0；
- 枯竭时 +0.5 暴伤；
- 余烬机制在魂火耗尽时提供下击必暴。

攻击流程：

```text
主动技能判定与前扣魂火
  → 基础伤害 + 技能倍率 + heavy 倍率
  → 流派机制触发（灼烧 / 反弹 / 回魂火 / 扣血换攻等）
  → 暴击判定 → parry/block → 应用伤害
  → 命中回魂火 on_hit(1)
  → 溅射 / AOE → 击杀检查 → 击杀钩子（含击杀经验，见 5.7）
  → Boss 形态拦截 → 吸血 / 连击 / 反击 → 清理临时状态
```

流派机制必须走统一出口，避免同名不同义。战斗层与持久层继续隔离：Build 临时增量胜利后同步，失败 / 中途退出回滚。

**击杀即判胜（v6.57）**：任何伤害来源让敌方单位 HP 从 >0 变 0 时（下沉到 `Unit.apply_damage`），立即排队一次胜利判定，不再依赖单一 `_on_kill` 路径。Boss 多形态在最终形态归零即当帧判胜并锁输入，杜绝"已死但能踩格子却拖到下一回合才胜利"的问题。

**敌方死亡掉落物**：敌方单位死亡有概率掉落血球，`item_battlefield_data.json` 配 `name` / `description`（含 `{v}` 占位符用 `heal_percent` 替换）。鼠标悬停掉落物时复用战场信息面板，显示 JSON 里的完整描述（如"血球 / 拾取后回复 25% 最大生命"），不再硬编码文案。

### 5.10 熔铸单位

保留为单一功能节点：牺牲一个单位，获得该职业专属 `melt_` 防具。

- 单位 `is_dead = true`，HP = 0。
- 产出防具不可修改、不可卖、不可合成、不可覆盖。
- 熔铸防具绑定到亡者，复活后可取回。
- 熔铸后第 1/2 技能格随单位死亡失效。
- 熔铸第 3 个单位会导致队伍全灭，本局结束。
- **代价周期（v6.54 确认）**：熔铸的牺牲只在当前 3 天 cycle 内有效；进入下一个 cycle 时 `GameState.start_new_cycle` 会把所有单位 `is_dead=false` 复活，熔铸掉的单位无偿归队。这是有意设计——熔铸是"局内战术取舍"而非永久损失，不跨 cycle 累积代价。

v6 不再把熔铸防具作为普通防具来源；它是伤亡价值化出口，不进入防具 roll 池。

**熔铸确认界面（v6.56）**：确认弹窗用结构化奖励预览分区展示——图标框（品质色描边）+ 防具名一行，下方独立信息区逐条列出数值与词条描述（如"攻击 +5，攻击 +20%" / "物减 +10% / 魔减 +8%"），让玩家判断这次牺牲是否值得。数值/描述来自 `item_data.json` 的 `description` 与 `melt_armor_effect`，不在 UI 硬编码。

### 5.11 竞技场

★ v6.10 起竞技场同步局内机制（原 v5 口径已废止）：

- 战斗内核 `ArenaBattle` 接入简化魂火与六流派机制，复用 `BuildManager.get_effective_school_level` 与各 ratio 纯函数：烈焰灼烧、守护反弹、献祭扣血换攻、轮回击杀回魂火、余烬魂火耗尽必暴；灰烬因 1v1 无移动故不触发地块。

## 七、试玩观察指标

### 目标区间

- 开局 roll 用时 <45 秒。
- 战后防具 roll + 领取用时 <60 秒。
- 魂栈停留 <60 秒。
- 燃烧态占比 40–60%。
- 枯竭态占比 15–30%。
- 归零 <10%。
- 三天通关率 >30%。
- 主动技能消耗提示可见率 100%。
- 防具 roll 覆盖 / 放弃决策出现率 >30%。
- 遗物三选一跳过率 <20%。

### 人工观察

- 玩家是否能一句话说出自己单位的 build。
- 同单位不同开局技能是否真的产生不同玩法。
- 同流派并入升 Lv 是否有即时爽感。
- 满槽覆盖是否痛但不困惑。
- 1 槽单位是否显得过于单薄。
- 3 槽单位是否造成认知负担。
- 消耗型遗物是否产生“现在用还是留着”的判断。
- 玩家是否还会寻找“方向 / 连通 / 词条重洗”等旧操作。

### 主要风险

1. 六流派机制接线与竞技场对齐工作量大。
2. 防具 roll 价格沿用商店数据，节奏可能偏贵或偏便宜。
3. 开局无重掷增加运气方差。
4. 技能与流派共鸣数值已冻结为「有效 Lv +1，上限 4」；待试玩确认是否会掩盖品质差异（common + 共鸣相当于 rare）。
5. 3 槽单位前期可能过强或信息过载。
6. 删除连通 / 方向后，部分老玩家可能感到深度下降。
7. 竞技场暂不同步，短期会出现两套装备口径。

## 八、设计哲学

- **选择而非计算**：玩家定流派、定给谁、定覆盖谁；系统跑腿。
- **单件即机制**：第一件装备就改变打法，不靠凑数。
- **同流派并入**：后续装备升同一条机制，不制造背包。
- **槽位是引擎数**：单位 1/2/3 槽代表能同时开几个流派。
- **技能是随机起点**：roll 池受单位可装备限制，不写死流派身份。
- **转职是固定第二格**：不被 roll、不被覆盖，保持身份感。
- **遗物统一化**：取消独立光环系统，只保留持续型 / 消耗型两种生命周期。
- **成长自动化但来源清晰**：等级不再制造操作（击杀自动给经验、自动升级、带仪式感反馈），build 差异优先于等级差异；玩家能看到当前/所需经验，但不用手动操作。
- **删除冗余比新增更有价值**：方向、连通、背包管理、商店比价都退出玩家层；v6.59 连难以理解的站位阵型系统也一并移除，build 深度回归单单位流派选择。
- **装备重要性靠机制表达**：不是让玩家更忙，而是让每次选择更有后果。
- **主线与竞技场口径统一**：核心 build 机制与经验规则在主线和竞技场保持一致。

## 十一、整局可玩性评估（v6.59，结合代码）

本章评估**整局游戏**的可玩性，覆盖战斗 / 经济 / 地图 / 成长 / 防具 / 闭环，而非单一系统。基于当前代码实现与实际数值，非纯设计推演。

**总体结论**：v6 完成了从"配装模拟器"到"选择组成 build"的转向，核心手感目标（选择而非计算、单件即机制）在代码层成立。经 v6.54 澄清后，转职无等级门槛、熔铸代价仅局内 3 天均为**有意设计**（文档已对齐），不再是问题。当前主要剩 **3 个体验断点**：封顶 roll 浪费、金币仅够约 8 次 roll、魂火枯竭态无负面；另有一处配置失效（宝箱权重，v6.54 已修代码）。

### 11.1 核心循环与决策密度 — 成立

完整循环：`开局选 3 单位 → 3 次主动技能 roll 落位 → 地图 3 天 → 战斗 → 战后防具 roll → 领取台决策 → BOSS → cycle 结算 → 回营地`。全程无终局、无限循环（设计如此，非死局）。

与 v5 对比，玩家的日常操作被压缩到三类决策（开局技能、战后防具、遗物三选一），系统承担所有计算——这是 v6 最重要的达成。第七章的决策密度表（战斗内 ★★、地图查看 ★）与实际实现一致：战斗内玩家能移动/普攻/技能/急救/走位，但不能再摆方向、凑连通、管背包；v6.59 起站位阵型配合也已移除，走位不再隐藏触发额外机制。

**风险**：存在完整自动战斗流水线（`AllyAutoBattleManager`，默认关闭但一键托管）。它会捡血瓶、急救、按魂火阈值放技能、Boss 时爆发——对"魂火状态管理"这一核心微循环而言，一键托管等于把决策层整个跳过。若试玩发现多数玩家开自动，v6 的"选择"哲学在战斗层就是空转。

### 11.2 战斗系统 — 机制齐备，操作价值需验证

- 魂火三态阈值（`SoulFireManager:91-125`）：>0.5 燃烧（移动+1、溅射50%）、<0.2 枯竭（暴伤+0.5）、归零回正常。**注意**：文档始终强调"燃烧 / 枯竭 / 正常"的取舍，但代码里**受伤放大已删、恒为 1.0**——三态中"枯竭"只有正面（暴伤+0.5）没有负面。这与"魂火是张力资源"的设计哲学冲突：枯竭反而变强，玩家会主动追求枯竭而非避免。目标区间（燃烧占比 40-60%、枯竭 15-30%）因此可能完全失真。
- 六流派 hook **全部接线**（烈焰灼烧、轮回击杀回魂、灰烬地块、守护反弹、献祭换攻、余烬必暴），竞技场也同步。这解决了第七章风险 1 的大半。
- 伤害公式（减伤上限 75%、保底 10%、暴伤上限 2.0）与文档一致。
- 技能共鸣使有效 Lv+1（上限4）——第七章风险 4 已明确，试玩需确认 common+共鸣是否掩盖品质差异。

### 11.3 经济与 roll 节奏 — 偏紧，是主要怀疑点

| 项 | 实际数值 |
|---|---|
| 战斗金币产出 | START/NORMAL 250、ELITE 400、BOSS 600 |
| 一局总量 | 约 7–9 场战斗 ≈ **2000–3000 金** |
| roll 成本 | `100 + 50×次数`，累计到第 9 次需 2700 |
| 品质升级 | 200/500/1200/2500/5000 |
| 其他消耗 | 熔铸 200/500（单位升级 250–6000 已停用，v6.58 起经验自动升级） |

**结论**：一局总收入只够约 8 次 roll，且这是**不买品质升级、不熔铸**的前提。若玩家点了品质升级（200/500 起步），roll 次数骤减。第七章把"覆盖/放弃决策出现率 >30%"列为指标，但金币Constraints 下玩家根本没有足够多的防具去凑满槽——**该指标可能因为买不起 roll 而无法达成**。建议试玩时优先统计"人均 roll 次数"与"满槽决策出现率"的因果关系。

### 11.4 地图与成长 — 结构清晰，口径已对齐

- **地图结构**：3 天/cycle，Day1 四节点、Day2 九节点、Day3 单 BOSS。过天每单位 +1 槽（上限4）——已与前几轮修复对齐。
- **转职（v6.54 确认为有意设计）**：无等级门槛，Boss 战后进英灵殿免费转职。文档与代码已对齐，不再视作问题；等级不 gate 构筑身份，与"build 差异优先于等级差异"一致。
- **熔铸（v6.54 确认为有意设计）**：牺牲只当前 3 天 cycle 有效，新 cycle 单位复活归队。这是局内战术取舍而非永久代价，文档已明确。注意第七章"魂栈熔铸 ★★★★ 决策密度"的前提是玩家理解代价仅局内——若玩家误以为永久，决策重量会被高估。
- **成长（v6.61）**：经验唯一来源是击杀（按敌方强度），战后不再发经验，阵亡单位当战不获得。这比旧的"按人头平均发"更能体现"谁在打"，击杀多的单位等级会略高，但由于每局净增仍约 1–2 级、上限 6，等级依旧不构成主要策略维度，符合"build 差异优先于等级差异"。升级带仪式感反馈，当前/所需经验在所有单位信息界面可见。
- **熔铸代价当局有效（v6.54 已确认为有意设计）**：`start_new_cycle` 把所有单位 `is_dead=false`，熔铸掉的单位下局无偿返还。文档已承认这是"当局牺牲"，不再是口径错误；但需注意第七章把"魂栈熔铸"列为 ★★★★ 高密度决策的前提是玩家理解代价仅局内——若玩家误以为永久，决策重量会被高估。
- **遗物稀有度未实现**：15 个遗物数据里没有 `rarity` 字段，第七章"遗物三选一跳过率 <20%"的分级体验缺数据支撑。

### 11.5 防具玩法（v6.53/54）— 方向正确，两处断点

- 决策收敛为一次双选项选择（`ConfirmUI.show_choice`），信息透明；空槽新流派直接觉醒不弹面板；取消可重开装备界面——链路完整。
- 隐藏 bug 已修：旧链路"落位防具词条为空"导致词条即流派无法成立，现已全链路携带 `affixes`。
- **断点 1（高优先）**：强化封顶后纯浪费。`apply_armor` merge 分支 `level=min(count,cap)` 封顶后不涨，且强化不 append 实例、不动词条——主流派到 cap 后 roll 到同流派，Lv 不变、词条不进、槽不占，花钱打水漂。结合 11.3 的金币紧张，这个断点会被放大。
- **断点 2**：专精防具 `affix_schools` 接口已做，但 50 件防具数据全空，v6.54 功能未启用。
- 观察点：转向 100% 继承等级无成本，可能使玩家频繁转向刷高 Lv，削弱流派专精感。

### 11.6 闭环健壮性 — 基本可靠，存档是隐患

- 死局防护到位：`TurnManager` 有未激活波次修复、自动战斗有卡死强解锁。
- 存档为标准 ResourceSaver + 多处 auto_save，待领取防具已序列化。但 **ResourceSaver 直接覆盖写、无原子写/备份**，且防具 roll 结果以 `_current` 内存态持有——异常退出时结果丢失。这与之前出现的"roll 后黑屏/丢结果"现象吻合，是体验信誉的最大威胁。
- **配置与实现脱节**：`economy_config.json` 的宝箱权重仍含 armor，但 `Treasure.gd` 已写死 gold/soul/relic——配置形同虚设，调参无效。
- 竞技场资源部分隔离：金币独立，永久魂共享——第七章风险 7 已提，仍存在。
